## 1. 결론과 검토 범위

현재 코드는 캔들 기반 추정 CVD와 일봉 기반 OBV를 결합한 **종목 탐색 도구**로서, 세션 분리·절대 Gate·지표별 데이터 상태·상대 순위 등을 명시적으로 다룬다는 장점이 있다. 그러나 현재의 `SUCCESS`가 “요청한 최신 거래일 구간의 정상 데이터”를 보장하지 않으며, `--as-of` 역시 과거 시점 데이터의 완전한 재현을 보장하지 않는다. 신규 지표를 추가하기 전에 이 두 계약을 강화해야 한다.

검토는 인증, 수집, 정규화, 세션/시간, CVD, Pivot, OBV, 가격추세, ATR/과열, 유동성, 점수/Gate, 출력, 저장, CLI 전체를 대상으로 했다. 원본 코드는 수정하지 않았다. 참조 대화의 첨부 파일을 로컬 미리보기 경로에서 확보했으며, 사용자에게 제시된 `/mnt/data` 경로와 동일 이름의 업로드 파일을 분석했다. 별도의 과거 리뷰 문서는 제공되지 않아 **파일 헤더의 V1.1~V1.5 변경 이력**을 중복 방지 기준으로 사용했다.

### 증거 수준과 한계

- **재현 확인**: 원본 함수 정의와 상수를 AST로 로드해 합성 입력으로 실행한 결과. 실제 인증·API 호출·import 시 디렉터리 생성은 수행하지 않았다.
- **코드 확인**: 제어 흐름과 수식에서 확인되는 문제. 운영 환경에서의 발생 빈도는 측정하지 않았다.
- **조건부 위험**: API 데이터 정의, 조회 시점, 거래정지/무체결 등에 따라 나타나는 문제. 캡처된 실제 응답으로 검증해야 한다.

전체 소스 구문 분석은 성공했다. 아래 확인은 프로젝트 전체 테스트나 실전 API 통합 테스트를 대체하지 않는다. API의 세션 포함 범위·시장 제도·실측 가격에 관한 소스 주석은 **작성자의 기록**으로 취급했으며 독립적으로 사실 확정하지 않았다. 공식 명세 확인은 [키움 REST API 가이드](https://openapi.kiwoom.com/m/guide/index?dummyVal=0)를 기준으로 수행해야 한다. 가이드 검색 결과는 명세 조회 기능을 안내하지만, 이번 검토에서 세션별 원시 응답이나 주석의 실측 증빙을 확보하지는 못했다.

### F01 — 과거 조회의 시점 정합성 [P0]

**위치:** `fetch_daily_bars` L1015–1088, `_is_bar_day_complete` L474–488, `analyze` L1950–1951.

`base_dt`는 날짜이고, `_is_bar_day_complete`는 시계가 마감 이후인지 판단한다. 일봉 자체의 관측/수신 시각은 검사하지 않는다. 재현 결과 2026-09-14 16:00에 `regular`는 당일을 완료로 인정하고 `auto`는 제외한다.

소스의 실측 주장대로 일봉이 확장 세션을 포함한다면, 21시에 조회한 당일 확정 일봉을 `--as-of 16:00 --daily-scope regular`로 평가할 때 16시 이후 체결이 OBV·MA·ATR·유동성에 들어갈 수 있다. 실시간 16시 실행도 이후 변경될 일봉을 완료값으로 취급한다. **`regular`는 일봉 내용에서 애프터마켓을 제거하는 옵션이 아니다.**

수정 방향:

1. 데이터의 `daily_definition`과 완료 정책을 분리하고 지원하지 않는 조합은 오류 처리한다.
2. 정규장 전용 일봉이 필요하면 확인된 별도 원천 또는 정규장 분봉 재집계로 만든다. 현재의 혼합 일봉을 시간 필터만으로 정규장 일봉으로 바꾸지 않는다.
3. 과거 연구에서는 `event_time <= as_of`뿐 아니라 `available_at <= as_of`인 저장 자료를 사용한다. 수정주가는 나중에 바뀔 수 있으므로 원본 수신시각·수정 이력도 관리한다.

**완료 기준:** 당시 이용 불가능한 일봉을 추가해도 당시 후보·점수가 변하지 않아야 하며, regular 일봉 정의를 제공하지 않는 원천에서는 해당 실행이 거부되어야 한다. 기본 auto 경로에 이 위험을 무조건 확대 적용하지 않는다.

### F02 — 요청 구간 바깥 누락과 오래된 후보 [P1]

**위치:** `_trim_to_last_n_trading_days` L870–883, `analyze` L1931–1946, `calc_cvd` L1417–1459, after Gate L2242–2251.

최근 N일을 **관측된 분봉 날짜**로 선택한 뒤, absent_days도 관측 범위 `lo <= d <= hi`에만 적용한다. 최신일 자체가 없으면 검사에서 제외된다. 완료일 최신성은 달력 5일 초과, 장중 최신성은 세션 운영시간에만 적용된다.

합성 재현: 9/10·9/11 각 77봉, 일봉 거래일 목록에 9/14 포함, `requested_days=2`, 9/14 21:00 기준 → `SUCCESS`, `absent_days=[]`, `stale=False`. 최신 거래일이 빠졌는데도 오래된 2일을 정상 요청 구간으로 인정한다. 애프터마켓도 종료 후 최신성 Gate가 적용되지 않아 이전 세션을 현재 저녁 자료로 해석할 위험이 있다.

수정: 거래일력과 정책으로 **기대 구간을 먼저 선택**하고 분봉을 그 집합으로 자른다. 완료된 최신 세션이 있으면 해당 날짜와 종결 데이터가 존재하는지 검사한다. 장중에는 당일 포함 여부를 명시한다. 무체결·대상 제외는 데이터 결함과 분리하되 “현재 세션 신호 없음” 상태로 처리한다.

완료 기준: 첫날/중간일/최신일을 각각 통째로 삭제하면 해당 날짜가 누락으로 드러나야 한다. 오래된 날짜를 넣어도 requested window가 대체되지 않아야 한다. completeness 분모에도 완전 누락일을 포함한다.

### F03 — 세션 경계 봉의 종료 의미 [P1]

**위치:** `session_of` L347–363, `bar_bounds` L367–374, 기대 봉 수 L377–416, 수집 절단 L977–982.

모든 시작시각 봉에 `period`를 더한다. 15:30 봉은 5분봉에서 15:35, 30분봉에서 16:00까지 진행한 것으로 기록된다. 소스는 15:30을 단일가 체결 봉으로 설명하고 세션 완료를 15:35로 판단하므로, 30분봉의 최종 단일가가 15:35에는 제외된다. 60분봉의 15:00 봉도 16:00까지 진행한 것으로 계산된다. OTHER와의 분류는 시작시각만 보고, 20:00도 AFTER에 포함하는 양끝 포함 조건이다.

수정: 접속매매 구간, 세션 종료에 잘린 봉, 종가 단일가 이벤트의 범위를 별도로 정한다. 일반 봉은 검증된 원천 규칙에 따라 세션 종료에 제한하고, 단일가 봉은 즉시 확정 이벤트/별도 타입으로 다룬다. 수신 지연 여유는 봉의 실제 거래 범위와 분리한다. 단순한 `min(start+period, session_end)`만 적용하면 15:30 봉이 0분이 되므로 모멘텀·집계의 이벤트 처리도 함께 설계해야 한다.

완료 기준: 모든 지원 period에서 세션 마감+여유 이후 최종 종결 체결을 포함하고 다음 세션 시간은 포함하지 않아야 한다. 기간별 기대/상한 봉 수는 종목·날짜별 실제 캡처로 검증한다.

### F04 — 모멘텀 해상도와 공백의 품질 [P1]

**위치:** `_momentum_window` L1190–1237, 백분위 L2084–2085, Gate L2227–2230.

60분봉은 목표 30분보다 길어 `RESOLUTION_LIMITED`지만 Gate는 WARMING_UP/NO_DATA만 차단한다. 긍정 방향과 다른 조건을 채운 합성 결과는 `BUY_CANDIDATE`였다. CVD SUCCESS인 종목의 모멘텀은 상태를 따로 검사하지 않고 백분위에 들어간다.

또한 actual minutes는 첫 봉 시작~마지막 종료의 벽시계 길이로 측정한다. 중간 누락도 무체결과 동일하게 취급할 수 있으며, 하루 집계 completeness는 특정 30분 구간의 누락을 반드시 잡지 않는다. 일중 누락은 당일 완료 이전 completeness에서 제외된다.

수정: 목표 해상도에 맞는 모멘텀은 `momentum_status == SUCCESS` 및 구간 품질 충족 자료로만 순위/Gate에 사용한다. 60분 신호를 허용하려면 별도 horizon 이름과 정책/모집단을 사용한다. 예상 슬롯·수신 실패·확인된 무체결을 구분해 구간 coverage를 산출한다. 원천이 희소 체결 봉만 제공하면 무체결과 누락을 임의로 확정하지 않는다.

### F05 — 내부 반올림의 잔여 영향 [P1]

**위치:** OBV 반환 L1711–1713 → 비교 L2121–2122/L2218–2220, 가격 이격 L1779 → 과열 L1809, total L2148 → 정렬 L2300.

- OBV MA20은 정수로 반올림된 후 Gate에 전달된다. 합성 20일에서 실제 OBV=1, MA20=0.95가 반환 시 1/1이 되어 `OBV > MA20`이 거짓으로 바뀐다. 일반 거래량에서 빈도는 미측정이지만 경계 계약의 결함은 확정된다.
- 실제 이격 15.004%가 15.00%로 반환되어 `>15` 과열 판정과 -5점이 사라지는 사례를 재현했다.
- 총점도 소수 1자리로 저장된 뒤 정렬되므로 작은 차이가 동률로 바뀌고 목록 입력 순서가 순위를 결정한다.

수정: 계산값·비교값·정렬값은 원정밀도를 유지한다. `total_raw`, `obv_ma20` 원값, `close_vs_ma20_pct` 원값을 저장하고 출력 시 포맷만 적용한다. 동일 원총점의 순서는 종목코드 등 명시된 보조 기준으로 고정한다.

### F06 — 파싱과 유효성 계약 [P1]

**위치:** `_bar_dt` L322–331, `_f` L1095–1105, 분봉/일봉 행 검사 L969/L1069, CVD L1304–1311, 백분위 L2009–2012, ATR L1818–1844.

`_f('nan')`이 NaN으로 통과하는 것을 확인했다. `_f`는 무한대도 거부하지 않는다. NaN은 참값으로 행 필터를 통과할 수 있고 순위 함수도 None만 제외한다. `_bar_dt('20260914259900')`은 시각 파싱 실패 후 날짜 형식으로 폴백하여 00:00을 반환했다. 잘못된 시각은 거부되지 않고 OTHER 자료 등으로 남을 수 있다.

비정상 OHLC는 CVD 방향을 0으로 만들지만 거래량과 봉 수에는 포함한다. 고가/저가 누락이 많아도 정상 completeness와 정상 CVD 상태를 얻을 수 있다. ATR은 잘못된 TR을 건너뛴 뒤 남은 TR 14개 이상이면 SUCCESS를 반환하므로 최신일이 제외돼도 이전 ATR을 최신 종가로 나눈 값이 표시될 수 있다.

수정: 유한수·양수 가격·유효 날짜/시각·OHLC 포함관계를 정규화 단계에서 검증하고 reject reason/count를 남긴다. 정상 평평한 봉과 손상된 OHLC를 구분한다. 분봉은 12/14자리 시간 형식을 엄격히 요구한다. ATR은 최신 TR의 가용성·결측 정책·유효 TR 기간을 기록하고, 누락이 있는 재귀 평활을 정상 연속 시계열로 표시하지 않는다.

### F07 — 오류 분류·수집 상태·인증 복구 [P1]

**위치:** `_get_token` L599–647, `_kiwoom` L742–816, 수집 break L946/L1050.

1. 인증 신규 발급의 `subprocess.run`은 JSON 처리 try 밖이다. `TimeoutExpired`/curl 미설치 `FileNotFoundError`는 처리되지 않는다. 일반 조회도 FileNotFoundError를 처리하지 않는다.
2. `_kiwoom`은 401/403 이외 HTTP 상태를 성공 여부에 반영하지 않는다. JSON 429/5xx가 return_code를 생략하면 정상 dict로 반환될 수 있다. 비JSON 오류 페이지는 즉시 None으로 끝나고 일시적 서버 장애를 복구하지 않는다.
3. 실패·조회 종료·커서 반복·페이지 상한은 모두 단순 list 반환으로 합쳐진다. 실패한 뒤 모인 충분한 과거 자료가 지표 SUCCESS로 남을 수 있다.
4. 메모리 토큰이 있으면 `_kiwoom`이 expires_at 검사 없이 우선 사용한다. 만료 시 재발급은 구현돼 있지만 매번 첫 실패를 기다린다. 인증 발급 경로는 중앙 리미터를 통과하지 않는다.
5. broad token 메시지/403은 만료 외 권한 문제도 포함할 수 있다. 토큰 파일은 계정/앱/환경별 식별 없이 공유되고 직접 덮어쓴다.

수정: `FetchResult`에 rows·http_status·api_code·error_kind·pages·stop_reason·complete를 반환한다. 2xx/인증/429/서버/요청/파싱/스키마 오류를 분류한다. 조회 POST에 한해 제한 재시도와 Retry-After 정책을 적용하고 전체 deadline을 둔다. 인증도 공통 transport 예외/설정 관리에 넣는다. 캐시는 앱/환경 식별 및 원자적 저장을 지원하고 선제 갱신한다. 현재 순차 실행에서는 리미터의 lock 부재를 현존 경쟁 버그로 주장하지 않으나, 병렬화 전에 thread/process 범위를 설계해야 한다.

### F08 — 일봉 품질과 시계열 의미 [P1]

**위치:** 일봉 수집 L1064–1088, trading_days L1946, 계산별 SUCCESS L1723/L1785/L1866, 일봉 정의 주석 L296–310.

일봉은 행 개수로 MA/OBV/유동성 준비 여부를 판단하고 거래일 연속성·최신일·전체 수집 완료를 검사하지 않는다. 같은 종목 일봉을 거래일력 대용으로 사용하므로 두 API가 함께 빠진 날이나 거래정지일은 탐지할 수 없다. 0거래량을 제거하는 정책 때문에 “최근 거래일”이 “최근 체결일”로 바뀔 수 있다.

주석은 2026-09-14 전후 일봉 정의가 정규장 종가에서 확장 세션 마지막 가격으로 바뀌었다고 기록한다. 이 주장이 맞다면 MA·OBV·ATR은 다른 정의의 입력을 한 시계열로 처리한다. 이미 한계를 명시한 것은 장점이지만 표시만으로 비교 가능성이 회복되지는 않는다. 조정가격과 미조정 거래량의 기업행동 처리도 별도 검증이 필요하다.

수정: 외부 거래일력·종목 상태·daily_definition을 별도 모델로 둔다. 공식 정규장 기준과 확장 세션 기준을 일관된 원천/재집계로 구성하고, 재구성 불가능한 전환 구간에는 quality flag를 둔다. 최신일·중간 공백·기업행동·워밍업을 지표별 품질에 반영한다. 자동화된 수익성 판단은 이 계약 검증 이후에 진행한다.

### F09–F11 — 기록·표시·CLI [P2]

**재현 기록(F09, L2441–2526):** config_hash에는 40/35/15/10 배점, 과열 경계/페널티, Gate 방향/비율 조건, 전체 임계값이 들어 있지 않다. 동일 버전 문자열로 가중치를 수정하면 같은 hash가 나올 수 있다. 지수 목록/갱신일/hash, 지표별 백분위 모집단 크기와 코드 집합, 제외 종목/실패 사유, 일봉 마지막 입력 날짜도 없다. `last_input_bar_at`은 전체 분봉의 최대값이므로 다른 종목의 지연을 가릴 수 있다. 원본 봉을 저장하지 않아 CVD 방식 변경 시 재계산이 불가능하다. 마지막 note L2522는 애프터마켓 포함이 미확인이라 쓰지만 앞 주석은 실측 확인이라고 써서 일관되지 않다.

**점수 의미(F10, L1490–1502/L1698–1704/L1985):** raw_score는 당일 포함 bull_ratio와 endpoint 다이버전스 배점을 여전히 사용한다. 최종 total은 완료 정규장 비율을 사용하고 다이버전스는 미배점이므로 둘은 같은 전략 점수가 아니다. raw_score가 최종 total에 직접 들어가는 것은 아니지만 JSON 소비자가 혼동할 수 있다. 상세 after CVD의 완료 비율 안내는 해당 after 비율을 “점수·Gate 사용”이라 표시할 수 있지만 실제 지속성 조건은 regular 비율이다. 상세 ATR 결측 경로는 과열 여부도 함께 숨기며, 실패 설명은 실제 상태 원인과 무관하게 MA20/15일 부족으로 단정하는 곳이 있다.

**CLI/운영(F11, L491–514/L2535–2616/L2812–2958):** 인증 실패 scan은 return하여 성공 종료처럼 보이고 목록 없음·detail 수집 실패도 명확한 실패 코드가 없다. 목록 JSON 오류/필수키 오류나 한 종목의 예외가 전체 실행을 멈출 수 있다. 중복 코드가 있으면 백분위 dict에서 합쳐지고 결과 list에서는 중복되어 비교가 왜곡된다. `--days`는 무제한인데 분봉은 최대 60페이지여서 대규모 요청이 조용히 상한에 걸릴 수 있다. import 시 `_DATA_DIR` 생성과 .env/stdout 변경도 라이브러리 테스트/재사용을 어렵게 한다. 모의 URL 상수는 있으나 CLI에서 선택할 수 없다.

수정: 전략 설정을 단일 객체로 만들고 코드/원본/유니버스 hash를 남긴다. schema_version과 실패 결과를 포함한다. `raw_score`는 제거 또는 `legacy_badge_score`로 명시하고 UI에는 실제 사용 입력의 세션·날짜·부족 사유를 표시한다. CLI는 명확한 반환 코드와 실행 요약을 제공하고 목록을 검증한다. 경로/환경 설정 및 import 부작용은 실행부로 옮긴다. 토큰·시크릿이 프로세스 인자에 실리는 curl 방식은 전용 HTTP 클라이언트 전환 시 함께 정리하고 인증 로그는 기본 비활성화한다.

### 5.1 수집 결과와 품질을 분리

```python
from dataclasses import dataclass
from typing import Literal

@dataclass(frozen=True)
class FetchResult:
    rows: tuple
    complete: bool
    stop_reason: str  # range_reached / exhausted / transport_error / page_limit
    pages: int
    error_kind: str | None = None

@dataclass(frozen=True)
class Quality:
    status: Literal['SUCCESS', 'PARTIAL', 'NO_DATA', 'NOT_APPLICABLE']
    reasons: tuple[str, ...]
    expected_dates: tuple[str, ...]
    observed_dates: tuple[str, ...]
    invalid_rows: int
```

`exhausted`는 원천에 더 이상 자료가 없다는 뜻이며 요청 기간 충족을 보장하지 않는다. 수집 complete와 지표 quality는 별도로 평가한다. 전송 실패 후 과거 봉이 충분해도 그 실패를 지우지 않는다.

### 5.2 기대 거래일을 먼저 선택

```python
def select_window(bars, calendar, as_of, session, days, include_active):
    expected = calendar.expected_session_dates(
        as_of=as_of, session=session, count=days,
        include_active=include_active,
    )
    keep = set(expected)
    selected = [b for b in bars if b.trade_date in keep]
    observed = {b.trade_date for b in selected}
    absent = [d for d in expected
              if calendar.is_complete(d, session, as_of) and d not in observed]
    return selected, expected, absent
```

구현 시 거래일력은 독립된 거래일 정보를 사용하고, 종목별 무체결/대상 제외를 별도 품질 사유로 처리한다. 정규장과 애프터마켓의 기대일은 시행일·대상 여부·당일 진행 여부에 따라 다르다.

| RVOL/Volume Z-score | 같은 시간대의 과거 거래량 대비 상대 강도 | 거래일/시간대 정합성과 충분한 baseline |
| 신호 변경 이력 | 후보 진입/이탈과 실제 사용 입력·조건 변경 추적 | 실행 간 모집단·설정 차이 함께 표시 |
| 모집단 안정성 표시 | 전체 목록 대비 성공률, 항목별 n, 순위 신뢰 범위 표시 | 실패 종목도 실행 결과에 보존 |
| 정규장/확장 세션 비교 연구 | CVD와 일봉 정의를 통제한 실험 | 혼합 시계열 구간 처리 및 정의 일관성 |
| walk-forward 검증 | 방향/가중치/추정 CVD의 실효성 검증 | 당시 자료와 당시 지수 구성 확보 |

RVOL이나 강도 최소 임계값을 바로 BUY Gate에 넣지 않는다. 추정 CVD는 OHLCV 변환이므로 실제 체결 매수 우위의 독립 증거라고 가정하지 않는다. 가격 위치·OBV·CVD 간 상관과 각 항목을 제거한 성능을 비교해야 한다. 평균 종가×거래량은 체결 가능성을 직접 보장하지 않으므로 실제 거래대금·스프레드·예상 체결비용은 데이터 확보 시 별도로 검증한다.

## 7. 테스트 전략

### 이번에 실행한 점검

| 점검 | 관측 결과 |
|---|---|
| 전체 소스 AST 구문 분석 | 성공 |
| 최신 거래일 누락 | SUCCESS, absent_days 없음, stale=False |
| 15:30 시작 봉 bounds | 5분은 15:35, 30분은 16:00 종료 |
| 16시 daily-scope | regular=True, auto=False |
| OBV MA20 반올림 | 실제 1>0.95가 반환 1==1로 변경 |
| 15.004% 이격 | 15.00% 반환, 과열 False |
| NaN 가격 파싱 | NaN 허용 |
| 잘못된 25:99 시각 | 당일 00:00으로 폴백 |
| RESOLUTION_LIMITED Gate | 조건 충족 합성 입력에서 BUY_CANDIDATE |

합성 봉은 제어 흐름 검증용이며 실제 키움의 모든 분봉 배열을 재현하지 않는다. 외부 API 정상 응답, 계정 권한, 시장 제도와 일봉 주석의 실측값을 이번 점검으로 검증했다고 주장하지 않는다.

### 필수 회귀/단위 테스트

1. **시점:** 09:00/첫 봉 직전·직후, 15:20, 15:30, 15:35, 16:00, 19:59, 20:00, 20:05. 지원 period 1/3/5/10/15/30/60 전체. 단일가·종결 봉과 미완성 봉을 분리.
2. **기간:** 첫날/중간일/최신일 삭제, 오래된 대체일 추가, 당일 분봉 0개, OTHER만 있는 날, 긴 휴장, 거래정지/무체결, 애프터마켓 시행 이전/전환 직후. expected window 불변 확인.
3. **CVD:** 정상 평평한 봉은 중립, OHLC 손상은 품질 저하, 총 buy+sell=유효 volume, 유한 정규화 값은 [-1,1], 일별 delta 합=전체 delta. 거래량을 같은 배수로 바꾸면 정규화 값 불변.
4. **모멘텀:** 30분 완전 구간, 첫 봉 워밍업, 60분 해상도 부족, 중간 누락, 확인된 무체결, 날짜/세션 공백. 상태별 순위/Gate eligibility 일치.
5. **OBV/MA:** 상승/하락/동가, 19/20/24/25/59/60/64/65/119/120일, MA 비교 경계, lookback N+1 최소 길이, 정규화 기울기 범위. 원정밀도와 표시 정밀도 독립성.
6. **ATR/과열:** 14/15일 경계, 최신 OHLC 손상, 중간 TR 결측, 15%/15.004% 경계, ATR 없음에도 이격 과열 판단 유지.
7. **순위/Gate:** 값 순서와 종목코드 순서가 반대인 입력, 평균 동률, 0/1개 모집단, PARTIAL 제외, NaN/Inf 거부, 입력 순서 변경 불변, duplicate code 거부. 점수 범위와 Gate 조건별 명확한 사유 검증.
8. **Pivot:** 마지막 right봉 부족 시 미확정, 동률 pivot 제외, 확인 시점 이전 자료에 신호 없음. 미래 봉을 추가해 과거 당시 확정값을 덮어쓰지 않음.

### 계약/통합 테스트

- 자격증명을 제거한 실제 응답 fixture로 필드/헤더/시간형식/정렬/빈 결과/종가 단일가/일봉 정의를 검증한다. 종목·날짜·주기·수신시각·명세 버전을 fixture에 기록한다.
- fake transport로 timeout, curl 미설치, 401→갱신 성공, 403 권한 실패, 429 Retry-After, 5xx JSON/HTML, 스키마 불일치, 반복 커서, 중복 내용 충돌, 상한 도달을 재현한다.
- 중복 봉의 OHLCV가 서로 다르면 현재의 “첫 값 유지”를 조용히 적용하지 않고 충돌을 기록한다. 페이지 배열 순서에 기대지 않는 cutoff 처리도 검증한다.
- 토큰 cache의 원자적 저장, 앱/환경 혼용 방지, 만료 전 갱신, 스냅샷 엄격 JSON(`allow_nan=False`)과 저장 실패를 점검한다.
- CLI는 정상/부분실패/전면실패를 반환 코드와 summary로 구분하고, 한 종목 실패가 다른 종목 분석을 막지 않는지 확인한다.

### 연구 검증

단순 적중률을 넘어 다음 세션/거래일의 사전 정의된 수익률, 거래비용 후 성과, 최대낙폭, 후보 수, 회전율, 데이터 제외율을 함께 측정한다. 당시 지수 구성으로 생존편향을 통제한다. 학습 구간에서만 가중치·임계값을 선택하고 검증/최종 평가 구간을 분리한다. 중첩 N일 신호의 의존성을 고려한 walk-forward와 필요 시 purge/embargo를 적용한다. F01의 당시 가용성 계약 없이 과거 `--as-of` 반복만으로 백테스트를 만들지 않는다.

## 8. 리팩터링 로드맵과 완료 기준

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 1 — V1.5.x 안전 수정 | F01 잘못된 일봉 조합 차단, F02 기대 구간, F04 eligibility, F05 원정밀도 | 위 재현 결함의 회귀 테스트 통과, intentional diff 명시 |
| 2 — V1.6 데이터 계약 | F03 봉/단일가 모델, F06 정규화, F07 FetchResult, F08 거래일/일봉 quality | 기간·경계·전송 실패마다 상태/사유가 손실 없이 전파 |
| 3 — 계산/입출력 분리 | 모델·설정·clock/calendar/client/storage 주입, indicator/gate 분리 | 계산부가 네트워크/파일 접근 없이 실행, 정상 fixture 값 유지 |
| 4 — 재현 기반 | 원본 archive/replay, source/config/universe hash, 지표별 모집단 기록 | 동일 입력·설정으로 동일 원점수/Gate/정렬 재생 |
| 5 — V2.0 연구/기능 | 시계열 정의 통일, walk-forward, RVOL/비용·상태 기능 실험 | 미사용 구간에서 기여 확인된 기능만 점수/Gate 반영 |

일괄 재작성보다 작은 변경으로 진행한다. 먼저 현행 정상 fixture의 계산 결과를 고정하고, 의도한 버그 수정은 별도의 before/after 결과로 검토한다. 이후 기존 CLI를 어댑터로 유지하면서 내부 모델을 교체한다. 병렬 수집은 처리시간 측정과 API 제한 범위 검증 후 도입한다. 현재 350종목의 최소 분봉/일봉 조회만으로도 700회이며 0.22초 간격 기준 대략 154초 규모이고 실제 페이지·왕복 지연·재시도는 더해진다. 개선 전 병렬화를 먼저 하면 공유 토큰/리미터·공통 as_of의 시점 정합성 문제가 커질 수 있다.

## 9. 권장 작업 순서

첫 작업은 **“기대 구간·입력 정의·지표 eligibility를 정상 판정의 계약으로 만들기”**다. 현재 존재하는 세션 모델과 JSON 저장을 다시 도입할 필요는 없다. 잘못된 regular 일봉 조합을 차단하고 최신일 누락과 해상도 부족이 후보가 되지 않도록 한 뒤, 봉 경계 계약·전송 오류 분류·일봉 품질·원본 재생을 연결한다. 그 이후 추가 지표와 임계값을 검증하면 개선 효과를 데이터 변화와 로직 변화로 나누어 평가할 수 있다.
