## 3. 애프터마켓 대응 우선 수정

### P0-1. 완료일 판정을 데이터 세션별로 분리

**근거:** 184~205행 `_MARKET_CLOSE_HOUR`와 `_is_bar_day_complete()`, 1294행 일봉 필터, 840~860행 CVD 완료일 집계.

현재 16:05에도 오늘을 완료일로 처리한다. API가 애프터마켓을 포함하면 아직 진행 중인 하루의 CVD가 completed_bull_ratio에 들어가며 `intraday_delta`에서 빠진다. 일봉에도 애프터마켓이 반영된다면 미완성 일봉 제외 문제가 다시 발생한다.

**권장:** `is_session_complete(trading_date, venue, session, as_of)`를 두고 다음을 구분한다.

- 정규장 전용 일봉·CVD: 정규장 종료 및 데이터 확정 기준.
- 애프터마켓 CVD: 20:00 종료 및 최종 봉 반영 기준.
- 전 세션 일봉: 실제 API의 정의와 마지막 포함 세션을 확인한 뒤 확정.

API 일봉이 정규장 전용이면 완료 시각을 일괄 20시로 미룰 이유가 없다. 반대로 확장 일봉을 15:30에 확정해서도 안 된다. 15:30·20:00 경계에서 최종 봉 수신 지연도 고려한다.

### P0-2. 요청 시장과 수집 데이터 범위를 명시

**근거:** 503행·592행 `stk_cd=code`; 수집 결과에 venue/session 메타데이터가 없고 별도 애프터마켓 선택·검증 경로도 없다.

데이터가 정규장만 오면 저녁 스캔은 오래된 흐름을 다시 평가한다. 확장 데이터가 자동으로 오면 현재 지표의 의미가 달라진다. KRX와 NXT는 별도 거래소이므로 애프터마켓 시간만 같다고 같은 입력으로 취급할 수 없다.

**권장:** 내부 모델에 `venue`, `session_scope`, `bar_start`, `bar_end`, `is_complete`를 추가한다. API 어댑터는 공식 명세에서 지원하는 요청 방식만 사용한다. 확인되지 않은 파라미터나 종목코드 접미사를 임의로 추가하지 않는다.

정규장·애프터마켓의 시각별 샘플 응답으로 마지막 봉, OHLC, 거래량, 일봉 변경 여부를 확인한다. 통합 시세와 개별 거래소 시세를 동시에 합산하면 중복될 수 있으므로 하나의 일관된 입력 경로를 선택한다. 향후 거래소별 봉을 보관할 때에는 시간만으로 중복 제거하지 않는다.

### P1-1. 390분 상수를 세션별 기대 봉 수로 교체

**근거:** 436행 `_MIN_PER_TRADING_DAY=390`, 497행 수집 페이지 추정, 861행 completeness.

정규장 390분과 애프터마켓 240분을 구분해야 한다. 단순 시간 산술상 5분봉은 각각 78·48개, 합계 126개다. 이는 API의 봉 시각·부분 봉 처리 확인 전 설계 예시다. 실제 합성 입력에서는 126개를 넣을 때 completeness가 **161.54%이고 SUCCESS**로 판정되었다. 추가 봉이 정규장 누락을 가릴 수도 있다.

**권장:** 날짜·세션·거래 가능 여부별 기대 타임스탬프와 수집 타임스탬프를 비교한다. 15:30~16:00을 연속 접속매매 구간으로 채우지 않는다. 별도 종가거래 등이 수집되면 독립 세션으로 분류한다. 수집 페이지 수 계산도 같은 세션 모델을 사용해야 한다.

9월 11일 이전 자료와 9월 14일 이후 자료에 동일한 확장 세션 기대량을 적용하지 않는다. 거래제도 시행일, 휴장일, 특수 거래시간, 종목별 애프터마켓 대상 여부를 반영한다. 대상이 아닌 종목은 `NOT_APPLICABLE`, 무체결은 별도 상태로 두어 API 누락과 구분한다.

### P1-2. 정규장과 애프터마켓 CVD·유동성·순위를 구분

**근거:** `calc_cvd()`는 날짜로만 Delta를 묶고, `calc_liquidity()`는 일봉 기반이며, `_finalize_scores()`에는 세션 구분이 없다.

**권장 기본안:** 기존 정규장 점수는 유지하고 다음 값을 추가한다.

```text
regular_cvd / regular_momentum / completed_regular_bull_ratio
after_cvd / after_momentum / after_traded_value
after_last_bar_at / after_data_status / after_eligible
```

저녁 후보는 정규장 추세 조건에 애프터마켓의 최신 데이터·유동성·방향 조건을 추가해 판정한다. 과거 여러 날의 양수 Delta 때문에 당일 저녁 매도 흐름이 가려지지 않도록 한다. 애프터마켓 조건의 수치 임계값은 실측·검증 후 결정한다.

애프터마켓 순위는 같은 세션을 수집하고 품질을 충족한 종목끼리 계산한다. 정규장 순위와 저녁 순위를 구분해 표시한다. 신규 세션의 역사 데이터가 부족한 초기에는 애프터마켓 RVOL 기준이 충분하다고 가정하지 않는다. Estimated CVD라는 성격도 유지한다.

## 4. 거래시간 변경과 별개로 남은 문제

### P1-3. 공통 as_of는 있지만 이후 분봉을 제거하지 않음

**근거:** 483~549행은 as_of로 과거 cutoff만 계산하며 `dt <= as_of`나 봉 완료 여부를 검사하지 않는다. 1719행 기준시각 이후 순차 조회된 데이터가 그대로 포함될 수 있다.

**영향:** 같은 기준시각을 표시해도 뒤에 조회한 종목은 더 최신 봉으로 평가된다.

**수정:** 시장 시간대가 명시된 as_of를 전달하고 API의 봉 시각 정의에 따라 `bar_end <= as_of`인 완료 봉만 계산한다. 출력에 실제 마지막 입력 시각도 기록한다.

### P1-4. 최근 30분이 실제 30분을 보장하지 않음

**근거:** 798행 `ceil(30 / period)`.

60분봉에서는 60분을 사용하고도 30분으로 표시한다. 무체결 봉 제거, 누락, 세션 사이 공백 때문에 최근 k봉이 30분보다 훨씬 오래될 수도 있다. 16:05에는 정규장 마지막 봉이 저녁 Momentum에 섞일 수 있다.

**수정:** 세션 내 실제 시간 구간으로 자르고 구간이 부족하면 WARMING_UP 등을 표시한다. 30분 계산에 60분봉을 사용할 때는 지원하지 않거나 더 짧은 원시 봉을 별도로 수집한다. 선택한 봉 주기로 불가능한 시간 해상도를 보장한다고 표시하지 않는다.

### P1-5. 날짜 전체 누락·당일 최신성 검사가 여전히 부족

**근거:** 868행 missing_days는 관측된 날짜만 검사한다. 877행 stale은 마지막 완료일이 5캘린더일보다 오래됐는지만 본다.

**영향:** 빠진 날짜가 더 오래된 거래일로 대체될 수 있다. 19시인데 마지막 분봉이 오전이거나 전일이어도 최신성 기준을 통과할 여지가 있다. 날짜별 50%·전체 80% 기준은 일부 집중 누락을 계속 허용한다.

**수정:** 기대 거래일 목록과 대조하고 활성 세션의 최신 봉 시각·무체결·거래정지를 구분한다. 전체 완성도뿐 아니라 날짜·세션별 품질 정책을 설정한다.

### P1-6. 토큰 만료 필드가 공식 응답과 불일치

**근거:** 300행 전후 `_get_token()`은 `token_expired` 또는 `expires_in`을 읽고 없으면 86400초로 저장한다. 공식 au10001 응답은 `expires_dt`를 제공한다. [키움 토큰 발급 공식 명세](https://openapi.kiwoom.com/guide/apiguide)

**영향:** 캐시가 실제 만료 시각과 어긋날 수 있다. 저녁까지 실행 시간이 길어지면 인증 복구가 더 중요하다.

**수정:** expires_dt를 정확히 파싱해 캐시하고 인증 만료 응답에만 1회 갱신 후 원 요청을 재시도한다. 반환 코드별 처리와 중앙 RateLimiter를 함께 보완한다. 임의 24시간 가정은 제거한다.

### P2-1. Gate와 점수의 bull_ratio 정의 차이

**근거:** 1402행 점수는 전체 bull_ratio, 1505행 Gate는 completed_bull_ratio를 사용한다. 완료일 비율이 없으면 전체 비율로 폴백한다.

**수정:** 의도된 차이면 출력에 두 정의를 명확히 쓰고, 완료일 지속성 점수라면 완료일 비율을 사용한다. 완료일이 없는 경우의 폴백이 당일 데이터를 완료일 근거로 대체하지 않도록 최소 완료일 수와 상태 정책을 둔다.

### P2-2. 당일 미완성 자료가 Price-CVD Pivot 확인에 사용됨

**근거:** 852행은 completed_pairs가 아니라 전체 day_last_close/day_end_cvd를 전달한다.

**영향:** 마지막 확인 봉이 진행 중이면 장중에 확정 표시가 다시 바뀔 수 있다. 미래 봉을 읽는 문제와는 구분되는 미완성 봉 문제다.

**수정:** 완료된 동일 세션의 일별 자료만 확정 Pivot에 사용하거나 provisional 표시를 분리한다.

### P2-3. 스냅샷 덮어쓰기·재현성

**근거:** 1675행 파일명은 지수와 분까지만 포함하고 쓰기 모드는 w다. 동일 분 재실행 또는 다른 period/days 실행 시 덮어쓸 수 있다. 원시 봉도 저장하지 않는다.

**수정:** 초·고유 실행 ID를 파일명에 포함하고 설정 해시, 코드 버전, 시장·세션·제도 버전, 실제 입력 시각을 저장한다. 필요하면 원시 입력을 압축해 별도 보관한다.
