## 1. 종합 판단

검증 시스템의 연구 파이프라인은 Stage 0~8까지 상당히 완성됐다. V1.5 계산 코어 동결, 과거 유니버스 복원, 일봉·분봉 데이터 레이어, historical replay, forward return, 포트폴리오 백테스트, 통계 검정과 ablation까지 구현됐다.

그러나 스캐너의 예측력이 확인된 것은 아니다. 현재 자료가 뒷받침하는 정확한 결론은 다음과 같다.

> **“효과가 없다”가 아니라 “현재 표본으로는 대부분의 효과를 판정할 검정력이 부족하다.”**

Probability Model과 운영 전환을 보류한 판단은 타당하다. 당장은 모델 개발보다 사라질 수 있는 분봉을 매일 보존하고, 일봉에서 발견된 OBV 후보를 다른 유니버스에서 재현하는 것이 우선이다.

## 3. 검증 과정에서 확인된 핵심 결과

### 3.1 Stage 2 초기 유의 결과는 철회됐다

h일 보유 전략에서 인접 날짜 신호는 h−1일의 가격 경로를 공유한다. 초기 분석은 날짜 간 독립성을 과도하게 가정해 신뢰구간을 좁게 계산했다.

수정 후에는 날짜 군집 강건 구간과 block bootstrap 구간을 함께 계산하고 더 넓은 구간을 사용한다.

| 항목 | 보정 전 | 보정 후 |
|---|---|---|
| h=20 `GATE_ALL` | +0.086%p, 유의 | 95% CI [−0.022, +0.197], 비유의 |
| 유의한 연도 | 17년 중 5년 | 17년 중 1년 |
| FDR 생존 결과 | 일부 | 0건 |

기존 결과를 삭제하지 않고 정정 배너와 결정 기록으로 보존한 것은 적절하다.

### 3.2 분봉 기반 V1.5 전체 신호는 아직 판정할 수 없다

BUY 여부, 점수 구간, 순위, Top-K, Gate 유무와 구성요소 제거를 검증했지만 관측 효과는 해당 표본이 검출할 수 있는 최소 효과의 0.11~0.53배였다.

따라서 현재 자료는 다음 두 주장 모두를 뒷받침하지 못한다.

- V1.5 신호에 예측력이 있다.
- V1.5 신호에는 예측력이 없다.

CVD의 추가 가치를 판정하려면 문서 추정상 h=20 기준 약 813~1,115거래일이 필요하지만 현재 replay 표본은 252거래일이다.

### 3.3 h=1 분석 중단은 타당하다

h=1에서 현재 관측 크기의 효과를 80% 검정력으로 탐지하려면 약 45~80년치 자료가 필요하다. 분석 격자에서 h=1을 제거하되 label은 계속 생성하는 정책은 합리적이다.

- 분석 기본 horizon: 3/5/10/20
- label 생성 horizon: 1/3/5/10/20
- h=1 직접 지정: 계산은 허용하되 검정력 경고

### 3.4 OBV의 추가 가치에 대한 후보가 하나 나왔다

Stage 2는 각 조건을 전체 유니버스와 비교했다. 선택지 C에서는 `PRICE`와 `PRICE+OBV`를 같은 날짜끼리 직접 짝지어 OBV의 주변 기여도를 측정했다.

| 대비 | 보유기간 | 평균 순수익 차이 | 95% CI | BH-FDR q |
|---|---:|---:|---:|---:|
| `PRICE+OBV` vs `PRICE` | 5일 | +0.0234%p | [+0.0051, +0.0432] | 0.024 |
| `PRICE+OBV` vs `PRICE` | 20일 | +0.0802%p | [+0.0248, +0.1408] | 0.020 |

이 결과는 발견이나 확증이 아니라 **재현 대상 후보**다.

- 같은 2010~2026 자료를 이전 단계에서도 사용했다.
- 관측/MDE 비율이 0.86과 0.97로 검출 한계에 가깝다.
- 상승 적중률 차이는 유의하지 않았다.
- 20일당 +0.080%p로 경제적 크기가 작다.
- 비용을 높이면 절대성과가 사라질 수 있다.

향후 표와 보고서에는 `delta`가 평균 순수익 차이인지 상승확률 차이인지 열 이름과 단위로 명확히 표시해야 한다. 현재 설명을 종합하면 FDR을 통과한 결과는 평균 순수익 차이이고 상승확률 차이는 비유의다.

### 3.5 유동성 Gate는 현재 형태에서 아무 역할을 하지 않는다

`PRICE+OBV`와 `GATE_ALL`이 같은 275,121행을 선택했다. 판정 가능한 표본에서 현재 유동성 조건이 한 번도 false가 아니기 때문이다.

권장 변경:

- Absolute Gate의 “유동성 값 존재” 조건은 제거한다.
- 유동성을 최소 거래대금, 주문 참여율, 예상 슬리피지 등 실행 가능성 조건으로 다시 정의한다.
- 신호 예측 feature와 체결 가능성 제약을 분리한다.

## 4. 현재 가장 시급한 확인사항

### 4.1 분봉 일일 수집 자동화

문서에서는 Stage 4가 완료로 표시되지만, 이는 최초 cache 구축 완료를 의미한다. 지속적인 데이터 운영은 완료되지 않았다.

저장소 점검 결과:

- 최신 분봉 Parquet 파일의 수정 시각은 2026-09-18이다.
- 자동 실행용 scheduler, workflow, PowerShell 또는 배치 파일은 발견되지 않았다.
- `minute-cache build` 명령은 있으나 일일 실행 장치는 없다.

따라서 Stage 4는 다음과 같이 구분하는 것이 정확하다.

| 세부 단계 | 상태 |
|---|---|
| Stage 4A — 최초 분봉 cache 구축 | 완료 |
| Stage 4B — 매일 증분 수집 | 미완료 |
| Stage 4C — 실패 재시도·경보·복구 | 미완료 |

자동화에 필요한 최소 기능:

1. 거래일 장 종료 후 실행
2. 휴장일·임시휴장 판정
3. 종목별 증분 upsert와 중복 방지
4. 실패 종목만 제한적으로 재시도
5. 마지막 거래일과 마지막 bar 검증
6. 예상 bar 수와 누락 구간 검사
7. 실패·부분 성공 알림
8. 일일 manifest와 품질 보고서
9. 다음 실행에서 미완료 run 자동 복구

분봉 API에는 과거 기준일 파라미터가 없으므로 자동 수집 누락은 향후 복구가 어려울 수 있다.

### 4.2 KRX KOSDAQ 지수 서비스 구독

2026-09-19 기준 `idx/kosdaq_dd_trd` 요청은 HTTP 401이었다. 서비스가 없어서가 아니라 현재 API 키에 구독이 없을 가능성이 높다.

사용자 확인이 필요한 항목:

- KRX Open API에서 `idx/kosdaq_dd_trd` 신청
- 가능하면 `idx/krx_dd_trd`도 함께 신청
- 신청 후 하루 범위의 작은 요청으로 권한 확인
- 권한 확인 후에만 전체 기간 수집 시작

### 4.3 KOSDAQ150 재현용 별도 사전 등록

`DATA_COLLECTION_PLAN.md`는 수집 계획을 잘 정의하지만 KOSDAQ150 재현의 최종 통계 판정 규칙은 별도 문서로 동결하는 편이 안전하다.

실행 전에 고정할 항목:

- 유일한 1차 가설: `PRICE+OBV > PRICE`
- primary outcome: 평균 net return
- primary horizon과 secondary horizon
- 단측 또는 양측 검정
- 비용 모델과 유동성 제약
- block length, bootstrap 횟수와 seed
- 부분 유니버스·상장폐지·가격 결측 처리
- KOSPI200–KOSDAQ150 의존성 측정 방식
- 성공, 실패, 불확정 판정 기준

## 5. 개선사항

### 5.1 형상 관리와 비밀정보 정리

저장소 확인 결과 핵심 구현과 결과 상당수가 Git 미추적 상태다.

미추적 또는 변경 상태에 포함된 주요 항목:

- `src/`
- `tests/`
- `configs/`
- `docs/`
- `reports/`
- `pyproject.toml`
- `cvdobv.py`
- data manifests

또한 `.kiwoom_token.json`이 변경 파일로 나타난다. 인증 파일은 절대 저장소에 커밋하면 안 된다.

권장 조치:

1. 소스, 테스트, 설정, 문서, 작은 manifest를 검토 가능한 커밋으로 정리한다.
2. API token, secret, 인증 cache를 `.gitignore`에서 명확히 제외한다.
3. 1.4GB 데이터 레이크는 Git에 넣지 않는다.
4. 데이터 파일은 별도 저장소나 백업에 보관하고 SHA-256 manifest만 형상 관리한다.
5. 현재 삭제 상태인 기존 문서·리뷰 파일이 의도된 삭제인지 확인한다.
6. Stage 0~8 완료 상태를 release manifest나 tag로 동결한다.

현재 단계 표는 연구 구현과 운영 상태가 혼합돼 있다. 다음 네 축으로 나누면 명확하다.

분봉 자동 수집은 투자전략 운영이 아니라 데이터 보존 작업이므로 Stage 9의 통계 증거를 기다리지 않고 즉시 진행해야 한다.

로드맵에는 “일봉 약 11년”이라는 초기 API 실측 표현이 남아 있지만 실제 연구 패널은 KRX 자료와 상장폐지 종목 보강을 통해 2010~2026년 약 16년이다.

문서에서 다음을 분리해 표시해야 한다.

### 5.4 CLI 문서 자동화

문서에 `cvdobv ...`와 `python cvdobv.py ...`가 혼재하고 일부 계획 명령과 실제 CLI 이름도 다르다.

개선안:

- 실제 parser에서 CLI reference 자동 생성
- `--help` 출력 snapshot test
- 설계상의 예정 명령과 현재 구현 명령을 별도 표기
- deprecated alias와 실제 명령의 대응표 유지

### 5.5 경제적 유의성 기준 추가

향후 후보 판정은 통계적 유의성만으로 결정하지 않아야 한다.

권장 게이트:

| 구분 | 예시 기준 |
|---|---|
| 통계 | CI, q-value, MDE, 검정력 |
| 경제성 | 비용 후 최소 초과수익 |
| 안정성 | 다른 유니버스 또는 새 기간에서 재현 |
| 실행 가능성 | 거래대금, 참여율, 예상 슬리피지 |
| 확률 품질 | base-rate predictor 대비 Brier 개선 |

통계적으로 유의하지만 거래할 가치가 없는 결과를 모델 개발 전에 걸러내야 한다.

### 5.6 두 유니버스 의존성 처리 개선

수집 계획의 ρ `<0.3`, `0.3~0.7`, `>0.7` 구간은 이해하기 쉽지만 통계적으로 임의적인 경계다.

다음 방법을 함께 검토하는 것이 좋다.

- 공통 거래일의 두 delta 계열을 함께 재표집하는 multivariate block bootstrap
- 날짜를 공통 cluster로 둔 joint inference
- 유니버스별 결과와 pooled 결과를 모두 보고
- 상관계수의 신뢰구간 보고
- 사전 등록한 유효표본 조정식 사용

ρ를 측정하기 전에 KOSDAQ150을 독립 표본으로 간주하거나 단순히 표본이 두 배라고 표현하면 안 된다.
