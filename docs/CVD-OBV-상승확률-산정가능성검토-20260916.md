# CVD/OBV 스캐너 상승확률 산정 가능성 검토 — 2026-09-16

검토 대상: `tools/kiwoom_cvd_obv_scanner.py` V1.5의 🟩BUY_CANDIDATE 판정을
"해당 종목의 주가 상승 확률"로 환산할 수 있는가.

결론: **현재 상태로는 불가능하다.** 인프라를 구축하면 일봉 기반 성분은
통계적 검정이 가능하나, CVD 성분은 데이터 깊이 한계로 유의미한 확률 추정이
어렵다. 아래는 모두 2026-09-16 실측값이다.

---

## 1. 확률을 말하려면 먼저 넘어야 할 기준선 — 실측

코스피200 199종목, 최근 260거래일(2025-08-25 ~ 2026-09-16) 일봉 전수 기준
**무조건부** 상승 확률(아무 종목이나 아무 날에 사서 h영업일 뒤 파는 경우):

| 보유기간 | 관측 수 | P(상승) | 중앙 수익률 | 평균 수익률 |
|---|---|---|---|---|
| 5영업일 | 50,708 | **50.3%** | +0.11% | +0.73% |
| 10영업일 | 49,713 | **50.4%** | +0.15% | +1.48% |
| 20영업일 | 47,723 | **51.7%** | +0.56% | +2.94% |

**이것이 의미하는 바**: 어떤 선별 방법이든 "상승 확률 52%"는 정보가 아니다.
동전 던지기와 같다. 스캐너가 가치를 가지려면 **기준선을 유의하게 초과**해야
하고, 그 초과분은 작을 것이므로 그것을 측정하려면 큰 표본이 필요하다.

---

## 2. 표본이 보이는 것보다 훨씬 작다 — 실측

관측 47,723건(h=20일)은 독립 표본이 아니다. 같은 날 종목들은 함께 움직인다.

| 항목 | 실측값 |
|---|---|
| 날짜별 상승비율 표준편차 | **21.9%p** (최저 7% ~ 최고 90%) |
| 날짜 내 상관(ICC) 추정 | **0.192** |
| Design effect (1 + (m−1)·ICC, m=199) | **39.0** |
| 유효표본 n_eff | 47,723 → **약 1,225** |
| 비중복 20영업일 윈도우 수 (260거래일) | **12개** |

날짜별 상승비율이 7%~90%로 흩어진다는 것은, 개별 종목의 등락이 종목 고유
요인보다 **그날 시장 전체 방향**에 지배된다는 뜻이다(사실). 즉 표본 수를
종목×날짜로 세면 안 된다.

---

## 3. 스캐너 후보로 좁히면 표본은 더 작아진다

분봉 API 깊이(255거래일, 4절) − 30영업일 워밍업 = **약 225개 as_of 시점**,
하루 후보 약 20종목 → 관측 약 4,500건. 여기에 보정을 적용하면:

| 가정 | n_eff | 관측 55%의 95% 신뢰구간 |
|---|---|---|
| 날짜 클러스터만 보정 (시간 중첩 무시, **낙관**) | ~970 | 51.9% ~ 58.1% |
| 비중복 20일 윈도우 11개 × 날짜 내 보정 (**현실적**) | **~47** | **40.8% ~ 69.2%** |

20일 보유 전략에서 연속된 날 진입한 포지션은 수익 경로의 19/20을 공유하므로
현실적 추정은 아래쪽에 가깝다.

**참고**: 55%를 50%와 80% 검정력으로 구분하려면 독립표본 약 **780건**이 필요하다.
낙관적 가정에서조차 간신히 닿고, 현실적 가정에서는 한 자릿수 배로 부족하다.

## 4. 데이터 깊이 실측 — 분봉과 일봉의 비대칭

삼성전자(005930)로 API 실제 한계를 측정했다.

| 데이터 | 실측 깊이 | 범위 | 제약 요인 |
|---|---|---|---|
| 5분봉 (`ka10080`) | **255 거래일** | 2025-09-01 ~ 2026-09-16 | **API 자체 한계** |
| 일봉 (`ka10081`) | **2,684 거래일** | 2015-10-05 ~ 2026-09-16 | API 여유 있음 |

분봉 255일이 API 한계임을 확인한 방법: `bdays=600`으로 요청 시 클라이언트
cutoff는 850캘린더일(2024-05), 페이지 용량은 54,000봉이었으나 실제 수집은
19,915봉/255거래일에서 멈췄다. 즉 cutoff·페이지 상한 어느 쪽에도 걸리지 않았다.

### 요청 방식의 비대칭 (코드 확인)

- `fetch_daily_bars()` — body에 **`base_dt` 있음** (`tools/kiwoom_cvd_obv_scanner.py:1042`)
  → 과거 시점 직접 조회 가능
- `fetch_minute_bars()` — body는 `stk_cd`/`tic_scope`/`upd_stkpc_tp`뿐, **base_dt 없음**
  (`tools/kiwoom_cvd_obv_scanner.py:932`) → 항상 최신부터 역방향 페이징

그리고 `max_pages`는 `bdays`만으로 산정된다(`:927`). 따라서 `--as-of`를 과거로
지정해도 **그 시점까지 페이지가 닿지 못하고** PARTIAL로 끝난다.

다만 시점 절단 로직 자체는 이미 정확하게 구현돼 있다 — `if bar_end > as_of:
continue` (`:981`). 즉 **룩어헤드 방지는 되어 있고, 과거 도달 수단이 없는 것**이다.

## 5. Gate 6조건 중 절반은 지금도 깊은 백테스트가 가능하다

`_compute_gate()` (`tools/kiwoom_cvd_obv_scanner.py:2175`)의 절대조건을
필요 데이터별로 분류하면:

| Gate 조건 | 필요 데이터 | 백테스트 가능 구간 |
|---|---|---|
| 종가 > MA20 | 일봉 | **11년** |
| OBV 정규화기울기 > 0 **및** OBV > OBV MA20 | 일봉 | **11년** |
| 유동성(20일 평균 거래대금) 존재 | 일봉 | **11년** |
| CVD 정규화Δ > 0 | 분봉 | 255거래일 |
| CVD 정규화 모멘텀 > 0 | 분봉 | 255거래일 |
| 매수우위일 비율 ≥ 50% | 분봉 | 255거래일 |

11년이면 비중복 20일 윈도우가 **134개**로, 현재 12개보다 11배다. 일봉 성분만
떼어내 먼저 검정하는 경로가 열려 있다.

또한 코드 자신이 이 임계값들을 검증 전 값으로 선언하고 있다 — `_compute_gate()`
docstring: "공통 절대조건(모두 검증 전 초기 설계값 — 의견)".

## 6. 확률 산정을 막는 나머지 요인

### 6-1. 생존편향·룩어헤드 (유니버스)

`data/index_stocks.json`에는 스냅샷이 **1개**(2026-09-08 갱신, 199종목)뿐이다.
시점별 구성종목 이력이 없다. 이 명단으로 255거래일 과거를 돌리면 그 구간에
포함된 **2026년 6월 정기변경**을 무시하게 되고, "그 사이 올라서 편입된 종목"이
과거 표본에 섞여 적중률이 위로 편향된다.

### 6-2. 거래비용

확률이 아니라 기대값으로 보면 더 나쁘다. 20일 중앙 수익률이 +0.56%인데,
증권거래세·수수료·슬리피지가 여기서 차감된다. 이번 스캔 후보 중
지역난방공사(071320)는 20일 평균 거래대금 7억원(유동성 1.5%ile)으로,
체결 비용이 신호를 상쇄할 수 있는 수준이다.

### 6-3. 시점 의존성 (오늘 직접 관측됨)

같은 날 09:37 스캔과 12:56 스캔에서 후보 14 → 20종목, **기존 후보 14개 중
7개가 이탈**했다. Gate 조건 중 "30분 모멘텀 > 0"이 스캔 시각에 좌우되기
때문으로 보인다. 어떤 종목의 "상승 확률"이 3시간 만에 바뀐다면, 그 값은
종목의 속성이 아니라 **스캔 시각의 함수**다. 확률을 붙이려면 진입 시각 규칙을
먼저 고정해야 한다.

## 7. 그래서 무엇을 할 수 있는가

### 지금 당장 가능 — 일봉 전용 서브모델 검정 (권장 우선순위 1)

Gate 6조건 중 일봉만 쓰는 3조건으로 11년 백테스트를 돌린다. 목적은 수익률이
아니라 **"CVD 없이도 기준선을 넘는가"** 를 먼저 확인하는 것이다. 여기서 초과분이
없다면 CVD 논의는 그 다음 문제다. `ka10081`이 `base_dt`를 지원하므로 추가
인프라 없이 가능하다.

### 중간 작업 — 분봉 캐시 1회 구축 (우선순위 2)

`ka10080`에 base_dt가 없으므로, 종목별 전체 히스토리(약 23페이지)를 **한 번만**
받아 로컬에 저장하고 이후 as_of는 오프라인 슬라이싱으로 재계산한다.
199종목 × 23페이지 ≈ 4,600콜, 초당 5회 제한에서 약 15~20분. 이후 225개 시점
재계산은 API 호출 0회다. `fetch_minute_bars()`에 캐시 경로를 추가하면 된다.

### 병행 — 유니버스 시점화 (우선순위 3)

지금부터라도 `update_index.py` 실행 결과를 날짜별로 누적 보관한다. 과거 소급은
KRX 정기변경 공시로 복원 가능하나 수작업이다. 이걸 안 하면 위 두 작업의
결과도 편향된 채로 나온다.

### 출력 형식 — 확률 대신

점추정 하나를 내놓지 말고 항상 **신뢰구간과 표본 수를 함께** 표기한다.
현재 표본에서는 그 구간이 50%를 포함하므로, 정직한 출력은
"적중률 55% (95% CI 41~69%, n_eff≈47) — 기준선 51.7%와 구분되지 않음"이다.

## 8. 정리

| 질문 | 답 |
|---|---|
| 지금 스캐너 출력만으로 상승 확률을 낼 수 있나 | **아니다.** 사후 검증 데이터가 전혀 없다 |
| 인프라를 만들면 낼 수 있나 | **일봉 성분은 검정 가능**(11년). CVD 성분은 255거래일 한계로 어렵다 |
| 나온 숫자를 확률로 쓸 수 있나 | 기준선(20일 51.7%) 대비 초과분만 의미가 있고, 현재 표본으로는 그 초과분이 0과 구분되지 않는다 |
| 가장 먼저 할 일 | 일봉 전용 3조건의 11년 백테스트 — CVD 없이도 edge가 있는지부터 |

이 검토는 **도구의 통계적 검정 가능성**에 대한 것이며, 특정 종목의 매수·매도
판단이나 투자 권유가 아니다.
