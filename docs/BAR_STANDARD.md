## 3. 기준 `bars-1.0`

| 항목 | 기준 | 이유 |
|---|---|---|
| 일봉 | `price_scope=REGULAR`, `adjustment_type=SPLIT_ADJUSTED`, 하루 한 행 | 공식 종가(15:30)·2010~ 이력과 같은 정의. 15:40 판단 시점에 알 수 있는 값 |
| 9/14 이후 일봉 | 1분봉 복원본(`DERIVED_MINUTE_1M`, 확정), 확정 전이면 잠정 봉(`DERIVED_MINUTE_1M_PROVISIONAL`) 또는 15:35~16:00에 받은 당일 봉 | 키움 일봉은 EXTENDED로만 온다 |
| EXTENDED 일봉 | 판정에 쓰지 않는다. `--allow-extended`로만 허용하고 결과에 표시 | 종가가 애프터마켓 최종가, 거래량에 애프터마켓 포함 |
| 빈 거래대금 | 같은 날 EXTENDED 공식 거래대금 × (정규장 거래량 / EXTENDED 거래량), 없으면 종가×거래량. `traded_value_est`로 표시 | 체결가 분포 반영. 규칙 하나 |
| 분봉 원천 | 1분봉(`period_min=1`)만 적재·수집 | 하나만 매일 수집되고 있다 |
| N분봉 | 1분봉 합성, 시계 정각 경계(09:00, 09:05 …). 지원 1·2·3·5·10·15·20·30·60 | 원본 5분봉 대비 99.99% 일치 |
| 계산 해상도 | 각 설계가 정한 값 — V1.5 5분, CVD 가속 1분 | 해상도를 바꾸면 검증된 설계가 아니다 |
| 신호 세션 | 정규장 | `--session after`는 기준 밖(참고용) |
| API 당일 일봉 | 15:35 전·16:00~20:05 = 미확정, 15:35~16:00 = 정규장, 20:05 뒤 = EXTENDED | `classify_fetched_daily` |

모든 reader의 입구는 `read_standard_daily()`(저장소), `StandardDailyCache`(실시간),
`resample_minute_table()`/`resample_bars()`(분봉)다.

## 4. 적재 기준 (2단계, 2026-10-06)

```bash
python cvdobv.py data-load provisional   # 16:10 — 밀린 날 확정 → 오늘 잠정 일봉
python cvdobv.py data-load daily         # 익일 08:30 — 정규장 확정 복원
python cvdobv.py data-load daily --since 2026-10-01   # 구간 직접 지정
python cvdobv.py data-load daily --dry-run            # 실행할 명령만 출력
```

| 단계 | 시각(스케줄) | 하는 일 | 일봉 |
|---|---|---|---|
| ① 잠정 | 당일 16:10, 월~금 — `scripts/provisional-load.bat`, 작업 "CVD 잠정 일봉 적재" | (밀린 날 확정 단계 전부) → `daily-cache provisional` | 1분봉 합. 가격 = 정규장 값, **거래량 = 정규장 + 15:35~16:00 시간외 종가 1분봉 합(근사)** |
| ② 확정 | 익일 08:30, 월~토 — `scripts/daily-load.bat`, 작업 "CVD 정규장 확정 적재" | `minute-cache catchup --period 1` → `daily-cache build`(KOSPI200·KOSDAQ150) → `daily-cache regular-from-minute` | EXTENDED − 애프터마켓 분봉. 공식 거래량(정규장 + 시간외 종가) |

두 작업 모두 같은 세 단계로 돈다(2026-10-14 개편). 16:10이든 08:30이든 어느 작업을
놓쳐도(PC 꺼짐·네트워크 장애) 다음 작업이 같은 로직으로 메운다.

1. **선행 점검** — 확인 구간(마지막 확정일 ~ 오늘)의 평일마다 지수 구성종목의 1분봉·잠정 봉·확정 봉
   수와 상태(`확정 완료` / `잠정만` / `1분봉만` / `미적재(또는 휴장)`)를 출력한다(`load_state.day_status`)
2. **밀린 날 먼저** — ① 1분봉 catchup(빠진 날 + 애프터마켓 확정 전에 받은 날) ② 빠진 잠정 봉
   (`daily-cache provisional --start … --end 어제 --missing-only`: 확정 봉도 잠정 봉도 없는 종목만)
   ③ 일봉 build ④ 정규장 확정 복원(잠정 봉을 덮는다)
3. **이 작업 몫** — 16:10이면 오늘 잠정 봉. 끝나면 같은 표를 "적재 후"로 다시 출력한다

| 놓친 작업 | 다음 작업이 하는 일 |
|---|---|
| 16:10(잠정) | 익일 08:30: 그날 1분봉 → 잠정 봉 → 확정 봉 순으로 메운 뒤 끝 |
| 08:30(확정) | 당일 16:10: 전날 확정을 먼저 끝내고 오늘 잠정 봉 |
| 여러 날 | 어느 작업이든: 밀린 날 전부 1분봉 → 잠정 → 확정을 끝낸 뒤 그 작업 몫 |

밀린 날의 잠정 봉은 곧 확정 봉에 덮인다. 그래도 먼저 만드는 이유는 확정이 실패하는 종목
(애프터마켓 분봉·확정 일봉 누락 등)도 그날 봉을 갖게 하려는 것이다.

| 규칙 | 내용 |
|---|---|
| 밀린 날 찾기 | 장부 `data/manifests/data_load_state.json`의 `confirmed_through`(마지막 확정 적재 때 애프터마켓 확정이 지난 마지막 날)부터 오늘까지 확인한다. 우선순위 `--since` > `--days` > 장부 > 최근 10거래일. `--since`일 때 catchup `--days`를 달력일 수로 넓힌다(기본 10이면 오래 밀린 날이 잘린다). 실패한 실행은 장부를 옮기지 않는다. 장부는 지워도 안전하다 |
| 장부를 옮기는 조건 | 실행이 끝나면 `confirmed_through` = min(애프터마켓 확정이 지난 마지막 날, **확정 정규장 봉이 지수 구성종목의 90% 미만인 첫 거래일 − 1일**). 거래일은 기준 종목(005930)의 저장된 1분봉·일봉으로 안다. 수집이 조용히 비어도 다음 실행이 그날을 다시 본다(2026-10-14 추가) |
| 1분봉 나눠 저장 | 같은 날을 두 번 받지만 한 번씩만 저장한다(2026-10-16, `minute_catchup.SessionStorePolicy`). 16:10: 정규장·시간외 종가만(애프터마켓 봉·커버리지 저장 안 함). 다음 날 08:30 다시 받기: 정규장이 이미 완전하면 애프터마켓·시간외 봉만 저장하고 정규장 **커버리지는 새로 쓴다**. 계획에 없는 (종목, 날짜)는 딸려 받아도 저장하지 않는다. 확정 복원은 1분봉 행이 아니라 그날 정규장 커버리지의 마지막 수집 시각으로 "애프터마켓 확정 뒤에 받았나"를 판정한다(`last_fetched_since`). 10/15 실측 기준 하루 약 4.6MB(1분봉 중복 정규장 121,587봉 + 16:00~16:10 애프터마켓 2,988봉) 감소 추정 |
| **NXT 메인마켓 거래량(A안)** | 2026-10-20부터 정규장 일봉 거래량 = KRX(정규장 + 시간외 종가) **+ NXT 메인마켓(09:00:30~15:20)**. 가격은 KRX 그대로. NXT 1분봉을 키움 `<코드>_NX`로 받아 `silver.minute_bars`에 `NXT:<코드>`로 저장(`minute-cache catchup --venue NXT`, 적재의 선택 단계). 더하는 것은 봉 시작 [09:00, 15:30)인 NXT 봉 합 — 프리마켓(08:00~08:50)·애프터마켓(15:30~20:00)은 제외. 표시 `NXT_MAIN_VOLUME_INCLUDED` / NXT 거래 종목인데 1분봉을 못 받았으면 `NXT_VOLUME_MISSING`(거래량 KRX만, 나중에 받으면 확정 봉을 다시 만든다). 확정 봉 리비전 2(이전 KRX만 확정 1을 덮는다). ## 7. 의미가 바뀌는 것 — 반드시 읽을 것

1. **2026-10-03 전후 결과를 같은 표에 섞지 않는다.** CVD/OBV·CVD 가속·데일리 스캐너의
   9/14 이후 MA·OBV·ATR·유동성이 애프터마켓 최종가 기준에서 정규장 종가 기준으로 바뀐다.
2. **과거 replay 재현**: `replay run --daily-scope auto --minute-source native`.
   기본값(`regular`·`standard`)으로 다시 돌린 결과는 이전 `gold.signals`와 다르다(분봉 0.01%,
   9/14 이후 일봉 정의).
3. **gold 산출물은 다시 만들지 않았다.** features·labels·daily signals는 수정 전 reader로
   만든 것이다(당시 9/14 이후 행이 두 번 들어간 구간이 있을 수 있다). 다시 빌드할지는 따로 정한다.
4. **사전등록 백테스트**: 로더가 이미 REGULAR만 읽었으므로 행 집합은 같다. 9/14 이후 복원 봉의
   빈 거래대금 추정만 종가×거래량에서 공식값 비율로 바뀐다(유동성 게이트, 최근 3주 구간).
5. **종가매수 당일 봉 경계**: 15:30 → 15:35(확정 여유 5분). 15:30~15:35 실행은 당일 봉을 쓰지 않는다.
6. **최신 거래일이 복원 전이면 그날은 빠진다**(예: 20:05 전 적재). 각 스캐너가 경고한다.
