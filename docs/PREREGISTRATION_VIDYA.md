작성일 2026-10-12 · 데이터 가족 **D3**(1분봉 CVD 흐름 + 로컬 기준 일봉)
· 실행 전 확정 · 이 문서의 sha256을 결과 JSON에 박는다

## §0 이미 본 것 / 보지 않은 것

이 사전등록은 **탐색이 아니다**(VIDYA는 이 데이터를 보고 고른 조건이 아니라
사용자가 지정한 외부 지표다). 그러나 **모집단은 이미 많이 쓰였다** — 아래를
전부 적어 둔다. 결과는 그만큼 할인해서 읽는다.

| 이미 본 것 | 어디 | 무엇을 봤나 |
|---|---|---|
| 가속 설계(accel-1.0)의 창·과열상한 선택 | `reports/CVD-가속설계-검증-20260927.md` | **이 250거래일 창에서** 3+7·과열 10%를 포함한 5개 설정의 수익률을 봤다(−2.1%~+64.7%). 즉 **가속 게이트 자체가 이 창에서 조정됐다** |
| 가속의 거래당 순수익 95% 구간 | 〃 | +0.709% [−0.207%, +1.683%], 0 포함 |
| 가속의 선행성 지표 | 〃 | 신호 전 상승폭 +0.25%, 상승 종목 비율 55.2% |
| 가속의 유니버스 대비 짝지은 평균 | `reports/backtest/accel-bridge.json` | 1분봉 구간 +0.022%p, 이긴 날 47.2% |
| 지평별 초과수익 | `reports/backtest/horizon-edge.json` | D+1~D+20 다섯 지평 전부 95% 구간 0 포함 |
| 일봉 대리 장기(2010~2026) | `reports/CVD-가속-일봉대리-장기검증-2010-2026-20260927.md` | 15.7년 D→D+2 −0.162%(구간 0 불포함). **대리 지표는 자체 관문을 통과하지 못했다**(게이트 재현율 52.1%, Top5 겹침 22.7%) |

**보지 않은 것**: VIDYA를 이 데이터에 한 번도 계산하지 않았다. 아래 파라미터는
공개 문헌의 통용값으로 **결과를 보기 전에** 고정한다.

**모집단 재사용 경고**: 가속 게이트가 이 창에서 조정됐으므로, 같은 창에서
VIDYA를 더한 결과가 좋아 보여도 그것은 **창에 대한 적합**일 수 있다. 확증은
2026-10-12 **이후** 데이터로만 가능하다.

## §1 정의 — 코드 함수 이름까지

### 1.1 기존 조건 (바꾸지 않는다)

`tools/cvd_accel_scanner.py`의 accel-1.0 게이트 5개를 그대로 쓴다.

```
f_d      일별 정규화 CVD 흐름 = Σ(거래량 × direction) / Σ거래량   (정규장 1분봉)
최근     mean(f, D-2 … D)        RECENT_DAYS = 3
이전     mean(f, D-9 … D-3)      PRIOR_DAYS  = 7
가속 A   최근 - 이전
게이트   ① f가 D-9…D 10거래일 연속 존재  ② A > 0  ③ 최근 > 0
         ④ 20일 평균 거래대금 존재      ⑤ 종가 ≤ MA20 × 1.10 (과열 제외)
```

- `f_d`의 원천은 `data/gold/cvd_daily_flow.json`(2026-09-27 생성, 395종목 ×
  259거래일, 정규장 1분봉, 봉 중앙값 381). 이 파일은 가속 검증에 쓴 것과
  같은 파일이다 — 흐름 계산을 다시 구현하지 않는다
- MA20·거래대금·수익률은 `tools/ab_backtest_b.load_all_bars`(= `bar_standard.
  read_standard_daily`, 정규장·수정주가, 빈 거래대금 단일 규칙 추정)

### 1.2 추가하는 조건 — VIDYA

Tushar Chande의 Variable Index Dynamic Average, **CMO 판(1995 개정판)**.
일봉 종가(기준 일봉 REGULAR)에 적용한다.

```
ΔP_t  = P_t − P_{t−1}
Up_t  = max(ΔP_t, 0)          Down_t = max(−ΔP_t, 0)
CMO_t = (ΣUp − ΣDown) / (ΣUp + ΣDown)        최근 n_cmo개 (범위 −1 … +1)
k     = 2 / (n_vidya + 1)
α_t   = k × |CMO_t|
VIDYA_t = α_t × P_t + (1 − α_t) × VIDYA_{t−1}
```

**고정 파라미터**: `n_cmo = 9`, `n_vidya = 20`.
근거 — CMO 9는 공개 구현의 통용 기본값이다. VIDYA 길이는 **표준 기본값이
없다**(QuantConnect 예시 20, TradingView 스크립트 14). 이 프로젝트가 이미
MA20(가속 과열 게이트)을 쓰므로 **20으로 맞춘다**. CMO는 −1~+1 척도를 쓴다
(|CMO| ≤ 1이어서 α ≤ k ≤ 1이 보장된다).
구현: `src/cvd_obv/indicators/vidya.py::vidya`, `cmo`.
시드: 워밍업 시작 이후 첫 `n_vidya`봉의 단순평균. 워밍업은 신호 시작
**250거래일 이전**부터 돌려 시드 영향을 없앤다.

**조건 두 가지** — 둘을 한 가족으로 등록한다(어느 쪽이 맞는지 미리 알 수 없다).

| 이름 | 정의 | 성격 |
|---|---|---|
| **V1** 상회 | `종가 > VIDYA_t` | 수준(level) 조건 |
| **V2** 상승 | `VIDYA_t > VIDYA_{t−1}` | 변화율 조건 |

> **설계 충돌을 미리 적는다.** accel-1.0은 `종가 > MA20`·`OBV > OBV MA20` 같은
> 수준 조건을 **의도적으로 뺐다**(이미 오른 종목을 고르게 되므로). V1은 바로
> 그 종류의 조건이다. 그래서 수익과 함께 **선행성 지표(신호 전 상승폭)**를
> 반드시 같이 본다 — 수익이 좋아지고 선행성이 깨지면 그것은 설계 목적을
> 되돌린 것이다.

### 1.3 집단

| 집단 | 정의 |
|---|---|
| `ACCEL` | 가속 5조건 통과 |
| `ACCEL_V1` | `ACCEL` ∧ V1 |
| `ACCEL_NOT_V1` | `ACCEL` ∧ ¬V1 |
| `ACCEL_V2` | `ACCEL` ∧ V2 |
| `ACCEL_NOT_V2` | `ACCEL` ∧ ¬V2 |
| `UNIV` | 그날 지수 구성종목 전체(동일가중) |

유니버스 명단은 `cvd_obv.universe.membership_intervals()`(이력만) —
`tools/ab_backtest_b.load_universe_intervals`와 같은 함수.

## §3 가설과 검정

### 주가설 (4개 — 이 가족 안에서 BH-FDR)

| # | 가설 | 계열 | 예측 방향 |
|---|---|---|---|
| **H1** | V1이 가속 집합을 가른다 | 날짜별 `mean(ACCEL_V1) − mean(ACCEL_NOT_V1)`, h=2 | > 0 |
| **H2** | V2가 가속 집합을 가른다 | 날짜별 `mean(ACCEL_V2) − mean(ACCEL_NOT_V2)`, h=2 | > 0 |
| **H3** | V1 추가가 유니버스를 이긴다 | 날짜별 `mean(ACCEL_V1) − mean(UNIV)`, h=2 | > 0 |
| **H4** | V2 추가가 유니버스를 이긴다 | 날짜별 `mean(ACCEL_V2) − mean(UNIV)`, h=2 | > 0 |

- **짝짓는 이유**: 가속 신호가 많이 나는 날은 시장이 오르는 날이다. 날짜별로
  차이를 만든 뒤 그 차이에 추론을 건다(`backtest/signal_gate.py`와 같은 이유)
- 두 집단 중 **한쪽이 빈 날짜는 제외**한다(H1·H2). 제외된 날짜 수를 보고한다
- 통계: 신호일 계열 **이동 블록 부트스트랩**, 블록 = 보유기간 = 2,
  재표본 4000, 시드 20261012. 95% 구간은 부트스트랩 분포의 2.5/97.5 백분위
- MDE = 2.8 × SE(= 1.96 + 0.84, 검정력 80%)
- q값: 4개 p값에 BH-FDR

### 판정 규칙 (기존 사전등록과 동일)

| 판정 | 조건 |
|---|---|
| `SIGNIFICANT_EDGE` | 95% 구간이 0을 제외하고 예측 방향, q ≤ 0.05 |
| `SIGNIFICANT_NEGATIVE` | 구간이 0을 제외하고 반대 방향 |
| `UNDERPOWERED` | 구간이 0 포함, \|관측\| < MDE |
| `NO_SIGNIFICANT_EDGE` | 구간이 0 포함, \|관측\| ≥ MDE |

### 미리 적는 예상

1. **H1~H4 모두 `UNDERPOWERED`일 가능성이 가장 크다**(추정). 250거래일 ·
   블록 2 → 유효 블록 약 125개. 기존 가속의 거래당 구간 폭이 ±0.9%p였고
   집단을 또 쪼개면 SE가 더 커진다
2. **V1(상회)은 선행성을 깬다**(추정). 신호 전 상승폭 D−10→D이 가속의
   +0.25%에서 **크게 올라갈 것**이다. V2(상승)는 덜 올라갈 것이다
3. V1 통과 비율은 가속 신호의 **절반 근처**일 것이다 — 가속 검증에서 선정
   종목의 54%가 MA20 아래였다

### 보조 결과 (서술용 — 판정에 쓰지 않는다)

- 커버리지: 가속 신호 중 V1·V2 통과 비율, 날짜당 통과 종목 수
- **선행성 지표**: 집단별 신호 전 상승폭 D−10→D, 상승 종목 비율
- h=5 같은 네 계열
- 가속 단독의 같은 두 계열(`ACCEL` vs `UNIV`) — 기준선
- 상위 5종목 동일가중 2일 회전 포트폴리오(ACCEL / ACCEL_V1 / ACCEL_V2).
  **원래 검증의 ARM/STOP/TRAIL 청산 엔진이 아니다** — 단순 회전이며 그렇게 표기한다
- 파라미터 민감도: (n_cmo, n_vidya) ∈ {9,14} × {14,20,30} 6칸의 H1·H2 관측값

### 하지 않을 것

1. 결과를 보고 `n_cmo`·`n_vidya`·h·과열상한을 바꾸지 않는다
2. 6칸 민감도 중 좋은 칸을 주 결과로 올리지 않는다
3. 지평을 2·5 외로 늘리지 않는다
4. V1·V2를 **합친** 조건(둘 다 통과)을 주가설로 추가하지 않는다 — 등록하지 않았다
5. 가속 게이트의 5조건을 손대지 않는다

## §4 무엇이 나오면 무엇을 하나

| 결과 | 행동 |
|---|---|
| H1 또는 H2가 `SIGNIFICANT_EDGE` **그리고** 그 집단의 신호 전 상승폭 ≤ +5% | `accel-1.1` 후보로 올린다. 스캐너에 **참고 열로만** 추가하고(게이트 변경 아님) 전향 기록을 2026-10-12 이후 데이터로 쌓는다. 전향 기록 60거래일 전에는 게이트에 넣지 않는다 |
| H1 또는 H2가 `SIGNIFICANT_EDGE` **그러나** 신호 전 상승폭 > +5% | 스캐너를 바꾸지 않는다. "수익은 올라가지만 선행성을 되돌린다"로 기록한다 — 설계 목적과 상충하므로 사용자 판단 사항으로 올린다 |
| 전부 `UNDERPOWERED` | 스캐너를 바꾸지 않는다. 필요한 표본 수를 계산해 기록한다 |
| `SIGNIFICANT_NEGATIVE` | 그 조건을 후보에서 제외한다 |

어느 경우든 **스캐너 게이트는 이 사전등록 하나로 바꾸지 않는다**(가속 게이트가
이 창에서 조정됐으므로 — §0).
