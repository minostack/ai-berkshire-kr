# 사전등록 MALEN — 이동평균 길이를 10·20·60 중 무엇으로 두어야 하는가

작성일 2026-10-21 · 데이터 가족 **D4**(KIS 일별 매수/매도 체결량 + 기준 일봉)
· 실행 전 확정 · 이 문서의 sha256을 결과 JSON에 박는다

---

## §0 이미 본 것 / 보지 않은 것

### 이 가설이 어디서 왔는가

사용자가 2026-10-21에 **"MA 길이 10·20·60 비교"**를 지시했다. 그 직전에
"왜 20인가"를 답하면서 확인한 사실은 다음과 같다 — **전부 길이가 아니라
'MA를 쓸 것인가'에 대한 것이고, 길이를 바꿔 본 적은 한 번도 없다.**

| 본 것 | 값 |
|---|---|
| 코드가 스스로 적은 상태 | V1.5 `_compute_gate` docstring: "공통 절대조건(**모두 검증 전 초기 설계값 — 의견**)" |
| 20의 유래 | 관례("월 ≈ 20거래일"). 실측으로 월 평균 **20.55거래일**(2008-06~2026-10, 219개월) — 관례와 맞지만 **선택 근거는 아니다** |
| MA20 **제거** 변형 (250거래일, 사전등록 아님) | V0 −41.3% / 게이트만 제거 −38.0% / **게이트+점수 24점 제거 −24.1%** |
| 그 개선의 성격 | 타이밍이 아니라 순위 효과로 보인다(그 리포트도 "직접 검정하지 않았다 — 추정") |
| MA 길이를 바꾼 검정 | **없다** |

**보지 않은 것**: **MA10·MA60으로 바꾼 수익률은 어떤 형태로도 계산하지
않았다.** 아래 주가설은 전부 수익 기준이고 엿보지 않은 상태다.

### 그러나 MA20의 수익은 이미 봤다 — 기준선이 엿본 값이다

8번(TRUECVD)·10번(WINDOW15)에서 **MA20을 쓴** 두 설계의 수익을 봤다:

| 본 것(10번, 창 15·MA20) | 값 |
|---|---|
| `accel` − 유니버스 | +0.0290%p [+0.004, +0.055] q=0.0338 **유의** |
| `accel` − 지수 | −0.4035%p **유의 음수** |
| `v15daily` − 유니버스 | −0.0317%p UNDERPOWERED |
| `v15daily` − 지수 | −0.4678%p **유의 음수** |

그래서 이 검정은 **"엿본 기준선(MA20)에 대해 두 대안을 붙이는" 구조**다.
MA10·MA60이 MA20을 이기면 그것은 새 정보이지만, **MA20이 이기는 것은
부분적으로 이미 아는 사실의 재확인**이다 — 리포트에서 그렇게 읽는다.

**대장 상태**: 사전등록 10개, 주가설 36개(실질 34). 이것이 11번째이고
**D4에서 세 번째**다 — 가족 안 다중비교를 할인해 읽는다(§2.1에서 D4 전체에
BH를 다시 건다).

## §1 정의

### 1.1 MA 길이가 들어가는 자리 — 설계마다 역할이 다르다

| 자리 | 가속 `accel` | 일반 `v15daily` |
|---|---|---|
| `종가 ≤ MA_n × 1.10` (과열 차단) | **쓴다** | 안 쓴다 |
| `종가 > MA_n` (상회 요구) | 안 쓴다 | **쓴다** |
| `OBV > OBV MA_n` | 안 쓴다 | **쓴다** |

**한 설계 안에서는 모든 MA 자리를 같은 길이로 바꾼다.** 즉 `v15daily`에서
MA60을 쓰면 `종가 > MA60` **그리고** `OBV > OBV MA60`이다. 자리마다 다른
길이를 섞는 조합은 **보지 않는다**(§3 하지 않을 것 3).

**미리 적는 메커니즘**(결과 해석을 위해서지 예측이 아니다):
- 가속의 과열 차단에서 **긴 MA는 상승장에서 더 엄격**하고(기준선이 아래에
  있다) 하락장에서 더 느슨하다. **짧은 MA는 가격을 바짝 따라가 거의 안 막는다**
- 일반의 상회 요구에서는 반대로 **긴 MA가 하락장에서 더 엄격**하다

### 1.2 비교하는 세 길이

```
MA10   MA20(기준선, 현행)   MA60
```

유동성 창(`LIQ_DAYS = 20`)은 **따라 움직이지 않는다.** 그것은 이동평균선이
아니라 거래대금 규모 측정이고, 데이터 가용성 판정에만 쓴다.

### 1.3 그 밖의 설계는 전부 고정

- 흐름 창 **15거래일**(가속 최근5+이전10, 일반 15) — 10번에서 확정한 현행값
- 과열 상한 **+10%**, 매수우위일 하한 **50%**, OBV 기울기 lookback **5**
- 흐름 원천 `J`(KRX 단독) — 주 패널
- 비용 `configs/costs/krx_v1.json` 왕복 0.409%

구현은 `truecvd_backtest.build_panel(ma_days=…)`로 쓴다. 인자를 비우면
8·10번 그대로 20이다.

### 1.4 모집단

`cvd_obv.universe.membership_intervals()`(이력만, 797종목).

## §3 가설과 검정

### 먼저: 짝 차이에는 벤치마크가 없다

```
(mean(MA10통과) − mean(유니버스)) − (mean(MA20통과) − mean(유니버스))
  = mean(MA10통과) − mean(MA20통과)
```

같은 날의 상수라 상쇄된다. 짝 차이에 "유니버스 대비"와 "지수 대비"가 따로
**없다**(7번의 V1≡V2 실수를 되풀이하지 않기 위해 등록 단계에서 적는다).

또한 **MA10−MA60은 등록하지 않는다.** H1·H2(또는 H3·H4)에서 그 차가
대수적으로 따라 나오고, 독립된 검정이 아니다. 필요하면 보조로 **서술만** 한다.

### 주가설 4개 (이 가족 안에서 BH-FDR)

전부 **양측**이다 — 짧은 쪽이 좋을지 긴 쪽이 좋을지 예측하지 않는다.

| # | 가설 | 계열 (h=2) | 예측 |
|---|---|---|---|
| **H1** | 가속에서 **MA10 − MA20** | 날짜별 `mean(MA10통과) − mean(MA20통과)` | 0과 구별 안 됨 |
| **H2** | 가속에서 **MA60 − MA20** | 〃 | 0과 구별 안 됨 |
| **H3** | 일반에서 **MA10 − MA20** | 〃 | **MA10이 나을 것**(아래 ②) |
| **H4** | 일반에서 **MA60 − MA20** | 〃 | 0과 구별 안 됨 |

- 두 길이 모두 통과 종목이 있는 날만 쓴다(한쪽이 비면 정의 불가)
- 통계: 신호일 계열 **이동 블록 부트스트랩**, 블록 = 보유기간 = 2,
  재표본 4000, 시드 **20261021**. 구간은 부트스트랩 2.5/97.5 백분위
- MDE = 2.8 × SE. q값은 **4개 p값에 BH-FDR**
- 판정: 구간이 0을 제외하고 양수면 `SIGNIFICANT_EDGE`(그 길이가 MA20보다
  낫다), 음수면 `SIGNIFICANT_NEGATIVE`(MA20이 낫다). 나머지는 기존 규칙

### 미리 적는 예상

1. **가속(H1·H2)은 작을 것**(추정). MA는 과열 차단에만 쓰이고 10번에서
   과열로 걸린 건수는 전체의 3% 수준이었다 — 건드리는 표본이 작다
2. **H3는 양수일 가능성이 있다**(추정, 방향 예측함). MA20 제거 변형에서
   `종가>MA20`을 풀었을 때 성과가 나아졌다(250거래일). MA10은 "거의 안 막는"
   쪽이므로 **제거에 가깝다.** 다만 그 변형 검증은 사전등록이 아니고 표본이
   짧다 — 틀릴 수 있다
3. **H4는 음수일 가능성이 있다**(추정). MA60 상회 요구는 더 엄격해서
   "이미 많이 오른 종목"으로 더 쏠린다
4. **통과 수는 크게 달라질 것**: 가속은 MA10에서 늘고 MA60에서 줄며,
   일반은 그 반대 방향일 것(추정)
5. 4개 전부 `UNDERPOWERED`로 끝날 가능성도 작지 않다 — 10번의 창 차이가
   +0.027%p(MDE 0.025)로 **간신히** 잡힌 크기였다

### 보조 결과 (서술용 — 판정에 쓰지 않는다)

- **세 길이 각각의 유니버스·지수 대비**(h=2). MA20은 10번의 재현이다
- MA10 − MA60 (H1·H2에서 따라 나오는 차)
- h=5의 같은 네 계열
- 길이별 **게이트 통과 수·통과율·Jaccard**(MA20 대비)
- 길이별 **과열로 걸린 건수**(가속) / **종가 ≤ MA로 걸린 건수**(일반)
- 길이별 집단 통계: 평균 순수익, 날짜당 종목 수,
  **선행성**(신호 전 D−10→D 상승폭, 상승 비율)
- 하위기간 2010-2017 / 2018-2026 (부호 안정성)

### 하지 않을 것

1. 결과를 보고 10·20·60이 아닌 다른 길이(5·30·120 등)를 추가하지 않는다.
   **다른 길이를 보고 싶으면 새 사전등록이다**
2. 보조(h=5, 하위기간)에서 좋은 칸을 주 결과로 올리지 않는다
3. **자리마다 다른 길이를 섞지 않는다**(예: 종가는 MA20, OBV는 MA60)
4. 흐름 창·과열 상한·매수우위일 문턱·배점·유동성 창을 함께 바꾸지 않는다 —
   **MA 길이 하나만** 움직인다
5. 신호 시작·끝을 결과를 보고 옮기지 않는다
6. `market_div`를 섞지 않는다(`J`)

## §4 무엇이 나오면 무엇을 하나

| 결과 | 행동 |
|---|---|
| 한 길이가 MA20 대비 `SIGNIFICANT_EDGE` **그리고** D4 전체 BH에도 생존 | **사용자에게 보고하고 결정을 받는다.** 에이전트가 임의로 스캐너 기본값을 바꾸지 않는다(MA20은 V1.5에서 내려온 값이고, 바꾸면 세 설계의 비교 기준이 끊긴다) |
| `SIGNIFICANT_EDGE`지만 가족 BH에서 탈락 | 바꾸지 않는다. "후보"로만 기록한다 |
| 전부 `UNDERPOWERED` / `NO_SIGNIFICANT_EDGE` | **MA20을 유지한다.** 스캐너에 "길이 10·60과 구별되지 않았다"를 적고 필요한 표본 수를 기록한다 |
| `SIGNIFICANT_NEGATIVE`(MA20이 낫다) | MA20 유지를 **측정 근거로** 확정한다 |
| 가속과 일반의 방향이 **반대**로 나온다 | 설계마다 MA의 역할이 다르므로(§1.1) **모순이 아니다.** 설계별로 따로 적고, 하나의 "최적 길이"로 묶지 않는다 |

**어느 경우든** `tools/kiwoom_cvd_obv_scanner.py`(V1.5, 해시 동결),
`tools/cvd_accel_truecvd_scan.py`(8번과 짝)는 고치지 않는다.
