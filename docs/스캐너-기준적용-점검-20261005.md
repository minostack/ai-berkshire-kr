## 1. 자동 적재가 실제로 돌지 않는다 — 최우선

**사실**: Windows 작업 스케줄러에 관련 작업이 없다.

```
Get-ScheduledTask | Where TaskName -match 'CVD|분봉|daily|load'
→ 프로젝트 작업 0건 (OneDrive·Realtek 등 시스템 작업만)
```

`scripts/daily-load.bat`(10-03 작성)과 `scripts/minute-catchup.bat`은 **파일로만
존재**한다. 예전 "CVD 분봉 누적"(16:10)도 지금은 없다.

**사실**: 저장소 1분봉·정규장 일봉은 **2026-10-02까지**다(10-05 행 0건).
오늘(10-05) 데이터가 없는 것은 적재 실패가 아니다 — 키움 1분봉 API도 10-02까지만
준다(가속 스캐너 probe 실측). 2026-10-03 개천절이 토요일이므로 10-05가
대체공휴일일 가능성이 높다(**추정**).

**영향**: 다음 거래일(10-06) 20:30에 아무 일도 일어나지 않는다. 1분봉 API 지평이
약 22거래일이므로 **방치하면 그 구간은 영구 손실**이다(기준 문서 §4와 같은 이유).

**조치**

```bash
schtasks /create /tn "CVD 일봉 적재" /tr "C:\a-ai\ai-berkshire-kr\scripts\daily-load.bat" /sc weekly /d MON,TUE,WED,THU,FRI /st 20:30
```

등록 후 `schtasks /run /tn "CVD 일봉 적재"`로 한 번 확인하고
`logs/daily-load/`를 본다. 예전 작업이 남아 있으면
`schtasks /delete /tn "CVD 분봉 누적" /f`.

## 2. 16:00~20:30 창에 당일 일봉이 없는데 경고가 없다

**사실** (`StandardDailyCache`를 기준시각만 바꿔 호출):

| 기준시각 | `today_scope` | 당일 일봉 |
|---|---|---|
| 2026-10-02 15:50 | `REGULAR` | API에서 붙인다 ✔ |
| 2026-10-02 18:00 | `INCOMPLETE` | **없다** |
| 2026-10-02 21:00 | `EXTENDED` | 적재 후에만 있다 |

기준상 맞는 동작이다(16:00~20:05 당일 봉은 애프터마켓 진행값). 문제는
**그 사실이 화면에 나오지 않는다**는 것이다.

원인은 경고 함수의 정의에 있다. `bar_standard.py:251`:

> `unrestored_days` = EXTENDED 일봉만 있고 정규장 봉이 없는 (종목, 날짜)

16:00~20:05에는 EXTENDED조차 저장하지 않으므로(적재 규칙상 버림) **당일이 아예
없는 상태는 여기 잡히지 않는다.** 실측: `unrestored_days()`가 빈 dict를 돌려주는데
당일 일봉은 없다.

**영향**: 가장 흔한 사용 시각(장 마감 후 저녁)에 MA20·MA60·OBV·ATR·유동성·과열이
**전일 기준**으로 계산되는데 표시가 없다. 가속 스캐너는 "흐름 기준일"(분봉)만
알려 주고 **일봉 기준일은 알려 주지 않는다** — 두 기준일이 어긋난 채 출력된다.

**조치**: 스캐너 요약에 분봉 기준일과 **일봉 기준일을 나란히** 출력하고, 다르면
경고한다. `closing_bet_scanner`의 `[데이터 기준]` 블록이 이미 그 형태다(§7).

## 3. 휴장일에 거짓 진단을 출력한다

**사실**: 2026-10-05(휴장 추정) **20:50**에 가속 스캐너를 돌리면

```
흐름 기준일(마지막 완료 정규장): 20261002
⚠ 오늘 정규장이 아직 완료되지 않았다 — 위 신호는 직전 거래일 종가까지의 흐름이다.
```

오늘 정규장은 5시간 전에 끝났다(열린 날이었다면). 코드가
`newest != 오늘` **하나만** 보기 때문이다 — `tools/cvd_accel_scanner.py:349`.

**영향**: 사용자가 "장중이라 그렇군"으로 읽고 넘어간다. 실제 원인(휴장 / 장중 /
적재 전 / 수집 실패)이 구분되지 않는다.

**조치**: 세 경우로 분기한다.

| 조건 | 문구 |
|---|---|
| 오늘이 거래일 아님(probe에 오늘 없음) | `오늘은 거래일이 아니다 — 마지막 거래일 {날짜} 기준` |
| 거래일인데 정규장 미완료 | 현재 문구 유지 |
| 거래일·정규장 완료인데 데이터 없음 | `⚠ 오늘 분봉이 수집되지 않았다 — minute-cache catchup 확인` |

거래일 여부는 이미 `probe()`가 알고 있다(API가 준 거래일 목록).

## 4. `--as-of` 과거 재현이 그 시점에 없던 일봉을 본다

**사실**: `StandardDailyCache`는 `trading_date <= as_of.date()`만 거른다
(생성 시각 필터 없음). 그래서 `--as-of "2026-10-02 15:50"`·`18:00` 모두
마지막 일봉이 **20261002**로 나온다. 그 10-02 정규장 복원본은 **그날 20:30
적재에서 만들어진 행**이다.

**영향**: 도구 도움말이 `--as-of`를 "회귀 검증용"이라고 안내하지만, 과거 시점
재현 결과는 **그 시점에 알 수 없었던 값**을 포함한다. replay 경로
(`src/cvd_obv/replay/windows.py`)는 별도로 `as_of` 컷을 하므로 영향이 없다 —
문제는 live 스캐너의 `--as-of`뿐이다.

**조치**: ① `as_of`가 현재보다 과거면 "재현이 아니라 참고"라고 경고하거나
② 일봉 행의 `adjustment_as_of_utc <= as_of` 필터를 옵션으로 넣는다(적재가 종목마다
수집 시각을 남기고 있어 가능하다).

## 5. 9/14 이후 거래대금이 100% 추정값이다

**사실**: 유니버스 351종목 × 거래일별 `traded_value_est` 비율

| 거래일 | 추정 비율 |
|---|---:|
| 2026-09-10 ~ 09-11 | **0%** |
| 2026-09-14 ~ 10-02 (14거래일) | **100%** (351/351) |

정규장 복원본에는 공식 거래대금이 없어 기준의 추정식(EXTENDED 공식 거래대금 ×
정규장 거래량 비율)을 쓴다. 규칙 자체는 기준 문서 §3에 적혀 있다.

**영향**: 아래가 모두 추정값 위에서 돈다.

| 쓰는 곳 | 비중 |
|---|---|
| V1.5 유동성 배점 | 100점 중 10점 + 게이트 조건 |
| 가속 설계 유동성 배점 | 100점 중 **20점** + 동점 처리 기준 |
| B(거래량 급증) 게이트 | 20일 평균 거래대금 ≥ 10억 |
| 종가매수 D형 | "거래대금 동반 신고가" 판정 |

20일 평균은 9/14 전(실측)과 후(추정)가 **섞인** 값이다.

**사실**: 종가매수 스캐너는 화면에 `(추정)`을 표시한다. **CVD/OBV·가속 스캐너는
표시하지 않는다.**

**조치**: 스캐너 요약에 "거래대금 추정 N/M종목"을 출력하고 스냅샷 JSON에 기록한다.
배점·게이트를 바꾸자는 것이 아니라 **추정 위에서 돈다는 사실을 보이게** 하자는 것이다.

## 6. 유니버스가 7일 묵었다

**사실**: 모든 스캐너가 같은 경고를 낸다.

```
⚠ KOSPI200: 2026-10-05는 구성종목 이력(2026-09-28) 밖 —
  index_stocks.json(as_of 2026-09-28) 명단 사용(7일 차이)
```

이력과 파일이 **둘 다 9/28**이다. 즉 기준은 설계대로 작동하지만(파일로 폴백 +
경고), 그 경고를 해소하는 절차(`/update-index`)가 자동화돼 있지 않다.

**영향**: 이 기간에 수시 편입·편출이 있었다면 반영되지 않는다(**불확실** — 실제
변경 여부는 확인하지 않았다). 경고가 매일 커진다.

**조치**: `data-load daily` 마지막 단계에 유니버스 신선도 점검을 넣고, 차이가
기준(예: 10거래일)을 넘으면 비정상 종료 코드로 알린다. 정기변경(6·12월)·수시변경
뒤에는 이력 갱신 → `update_index.py` 순서를 지킨다.

## 7. 데이터 상태 경고의 위치·형식이 도구마다 다르다

**사실**: 같은 정보가 서로 다른 자리에 나온다.

| 도구 | 데이터 기준 표시 | 위치 |
|---|---|---|
| **종가매수** | `[데이터 기준]` 블록 — 봉 기준 + 스캔 기준일 + **시장 최신 완료 거래일** + 데이터 상태 한 줄 | 결과 **앞** ✔ 모범 |
| A·B 선정기 | 유니버스 경고 2줄 | 결과 **뒤** |
| 가속 | 유니버스 경고(앞) + 봉 기준 1줄이 **수집 진행 로그에 섞임** | 분산 |
| V1.5 입구 | `[봉 기준]` 1줄 | 결과 **뒤** |
| 데일리 스캐너 | 명령별로 다름 | — |

결과를 먼저 읽고 경고를 나중에 보면, 이미 리스트를 신뢰한 뒤다.

**조치**: `bar_standard.describe()` + `universe.describe()` + 일봉/분봉 기준일 +
추정 비율을 묶어 **결과 앞에 한 블록으로** 출력하는 공통 함수를 만들고 네 스캐너가
같이 쓴다. 종가매수의 블록을 그대로 승격하면 된다.

## 8. `live_feed` 일봉 캐시 재생성 조건

**사실**: `StandardDailyCache` 1회 생성 = **17.64초**(351종목).
`live_feed._daily_cache()`는 `self._cache is None or (code not in self.codes)`일 때
캐시를 **새로 만든다**. `self.codes`는 `current_universe()`(오늘 명단)로 채운다.

오늘 측정에서는 2026-09-15 명단 ⊆ 오늘 명단이라 재생성 **0회**다. 그러나 조건
자체는 "명단 밖 종목을 만나면 전체 재빌드"이므로, 과거 명단에 있고 지금은 빠진
종목이 N개면 최악 **N × 17.6초**가 된다.

**조치**: 캐시는 한 번만 만들고, 포함되지 않은 종목은 **그 종목만** 추가 조회한다.

## 9. 그 밖 (낮음)

1. **분봉 호출량 증가**: `--period 5` 스캔도 1분봉을 받아 합성한다. 5거래일이면
   종목당 1페이지 → 약 3페이지로 늘어난다(351종목 기준 약 +2.5분, **추정**).
   V1.5가 출력하는 "분봉(5분) 수집" 안내문은 이제 사실과 다르다.
2. **`minute_catchup`의 `NO_DATA` 재시도**: 장부(`minute_catchup_state.json`)는
   `STILL_PARTIAL`만 적는다. 편출·폐지 종목은 매 실행 재조회된다. 지금 영향 0
   (과거 명단 = 현재 명단). 정기변경 직후에 수십 종목이 될 수 있다.
3. **gold 산출물은 수정 전 reader 산출물**이다(기준 문서 §7-3). 스캐너는 gold를
   읽지 않으므로 영향이 없고, **백테스트·ablation만** 해당된다. 다시 빌드할지는
   별도 결정 사항으로 남아 있다.
4. **`daily_scanner._STD_CACHE`** 키가 `(codes, 날짜)`뿐이다. 한 프로세스가 16:00
   경계를 넘겨 오래 살면 `today_scope`가 고착된다(1회 실행 도구라 실무 영향 낮음).

## 10. 확인했고 문제가 없는 것

- **입구 통일**: `read_standard_daily`를 features·labels·backtest engine·replay·
  A·B 선정기·종가매수가 모두 경유한다. 직접 `silver.daily_bars`를 읽는 곳은
  적재·복원 코드(`daily_history`, `krx_daily_panel`, `regular_from_minute`)와
  골든 fixture뿐이다 — 기준대로다.
- **유니버스 입구 통일**: `index_stocks.json`을 파싱하는 코드는 `universe.read_index_file`
  하나, 파일을 쓰는 곳은 `tools/update_index.py` 하나다.
- **`closing_bet_scanner`의 `allow_extended=True`**(441행)는 복원 후보를 읽기
  위한 것이고, 판정은 `eligibility()`(374행)가 EXTENDED 포함 창을 거른다 — 기준 위반이 아니다.
- **데이터 완결성**(유니버스 351 한정): 9/21~10/02 전 거래일 REGULAR 351/351,
  `unrestored_days` 0건. 전 종목 기준으로는 9/21·9/22가 378종목 미복원인데,
  이는 지수 밖 종목(1분봉 없음)이라 기준 문서 §8이 적어 둔 그대로다.
- **재현 정보**: 가속 스캐너 스냅샷에 `bar_standard`와 `universe_standard`가
  둘 다 기록된다(439·524행).
- **실행 확인**: V1.5 입구 `detail`, 가속 `scan --limit`, 종가매수, A·B 선정기
  B모드가 모두 정상 종료했다.
- **전체 테스트 통과**(2026-10-05 점검 시점, 실패·에러 0건). 기준 적용이 기존
  동작을 깨뜨린 곳은 없다.

### 다만 — 위 8건은 테스트가 보지 않는 영역이다

스케줄 등록 여부, 화면 경고의 유무·문구, 경고 위치, 캐시 재생성 비용은 현재
어떤 테스트도 검사하지 않는다. §2·§3은 회귀로 고정할 수 있는 성질이므로 고칠 때
함께 넣는다.

| 넣을 테스트 | 무엇을 막는가 |
|---|---|
| `test_16시_이후_당일_일봉이_없으면_경고한다` | `as_of 18:00`에서 일봉 기준일 경고가 사라지는 회귀 |
| `test_휴장일에는_장중이라고_말하지_않는다` | probe에 오늘이 없을 때 "아직 완료되지 않았다"로 돌아가는 회귀 |
| `test_거래대금_추정_비율이_요약에_나온다` | 추정 표시가 조용히 빠지는 회귀 |
