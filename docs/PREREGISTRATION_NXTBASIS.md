**그러나 이 질문 자체는 탐색에서 나왔다**: §8의 "부호 불일치 10.9%"를 보고

## §1 정의

### 1.1 두 기준

```
f_J (d)  = (buyJ − sellJ) / (buyJ + sellJ)
f_UN(d)  = (buyJ + buyN − sellJ − sellN) / (buyJ + buyN + sellJ + sellN)
```

- 원천: `silver.daily_trade_sides`,
  reader는 `cvd_obv.ingestion.kis_trade_sides.read_trade_sides()`
- `J` 행은 2026-10-19 적재분(run `kis_sides_20261019051637`)을 그대로 쓴다 —
  **재수집하지 않는다**(호출마다 분해가 미세하게 달라진다, 대비검토 §7.1)
- `NX` 행은 `tools/collect_trade_sides.py --market-div NX`로 2026-10-19에
  수집한 것을 쓴다
- **NX 결측 처리(미리 고정)**: 어떤 (종목, 날)에 `NX` 행이 없거나
  `quality_flags`에 `TRADE_SIDE_BOTH_ZERO`가 있으면 **그날 NXT 체결이 없는
  것으로 보아 (0, 0)을 더한다.** 즉 그 날의 `f_UN = f_J`가 된다.
  결측 행 수·종목별 결측률은 리포트에 사실로 적되, **판정은 이 한 가지
  처리로만 한다**(대체 처리로 다시 돌려 좋은 칸을 고르지 않는다)
- `J` 행이 없거나 `BOTH_ZERO`인 날은 **두 기준 모두 흐름 없음**으로 본다
  (NX만 있는 날을 UN에 넣지 않는다 — 기준이 비대칭해진다)

### 1.2 설계 — TRUECVD와 **같은 두 설계**, f만 바꾼다

`tools/truecvd_backtest.py`를 **import**해서 쓴다. 게이트·OBV·창 흐름·비용·
부트스트랩·판정을 새로 짜지 않는다.

| 설계 | 정의 | 재사용 함수 |
|---|---|---|
| `accel` | accel-1.0 게이트 5개(창 3+7, A>0, 최근>0, 유동성, 종가 ≤ MA20×1.10) | `accel_vidya_backtest.accel_from_flow`, `rolling_mean` |
| `v15daily` | V1.5 정규장 절대조건 중 일별 재현 가능한 5개(30분 모멘텀 제외) | `truecvd_backtest.obv_series`, `window_flow` |

- `v15daily`의 `normalized_delta` 가중치는 **그 기준의 합계**를 쓴다
  (`J` 기준은 `buyJ+sellJ`, `UN` 기준은 `buyJ+buyN+sellJ+sellN`)
- OBV·MA20·유동성은 **두 기준이 같다** — `silver.daily_bars`(KRX 단독 기준)에서
  온다. **일봉은 바꾸지 않는다.** 즉 이 검정은 "흐름만 통합 기준으로 바꾸면"에
  대한 답이고, "거래량까지 통합으로 바꾸면"에 대한 답이 아니다(§3 하지 않을 것 5)

### 1.3 모집단

`cvd_obv.universe.membership_intervals()`(이력만). TRUECVD와 같다.
NX 수집 대상은 **`J` 구분에 2025-03-04 이후 행이 있는 종목 전체**로 잡았다
(`--codes-from table`) — 현재 명단만 쓰면 생존 편향이 들어간다.

## §3 가설과 검정

### 먼저: 벤치마크가 상쇄된다는 것을 미리 적는다

기준 차이 계열은 **같은 날 안에서** 두 기준의 통과 집단을 비교한다.

```
(mean(UN통과) − mean(유니버스)) − (mean(J통과) − mean(유니버스))
  = mean(UN통과) − mean(J통과)
```

유니버스든 지수든 **같은 날의 상수라 상쇄된다.** 그러므로 기준 차이에는
"유니버스 대비"와 "지수 대비"가 따로 존재하지 않는다 — **하나다.**
(7번 사전등록에서 V1·V2가 대수적으로 같은 조건이었던 실수를 되풀이하지 않기
위해 등록 단계에서 적어 둔다.)

### 주가설 6개 (이 가족 안에서 BH-FDR)

| # | 가설 | 계열 (h=2) | 예측 |
|---|---|---|---|
| **H1** | `accel`에서 기준을 UN으로 바꾸면 수익이 **달라진다** | 날짜별 `mean(UN통과) − mean(J통과)` | **0과 구별 안 됨**(양측) |
| **H2** | `v15daily`에서 기준을 UN으로 바꾸면 수익이 **달라진다** | 〃 | **0과 구별 안 됨**(양측) |
| **H3** | `accel(f_UN)`가 유니버스를 이긴다 | 날짜별 `mean(통과) − mean(그날 유니버스)` | > 0 |
| **H4** | `accel(f_UN)`가 지수를 이긴다 | 날짜별 `mean(통과) − KOSPI200 수익` | > 0 |
| **H5** | `v15daily(f_UN)`가 유니버스를 이긴다 | 〃 | > 0 |
| **H6** | `v15daily(f_UN)`가 지수를 이긴다 | 〃 | > 0 |

- H1·H2는 **양측 검정**이다(기준이 더 좋아질지 나빠질지 방향을 예측하지 않는다).
  H3~H6은 기존과 같이 "> 0"을 예측한다
- 통계: 신호일 계열 **이동 블록 부트스트랩**, 블록 = 보유기간 = 2,
  재표본 4000, 시드 **20261019**. 구간은 부트스트랩 2.5/97.5 백분위
- MDE = 2.8 × SE. q값은 **6개 p값에 BH-FDR**
- 판정 규칙은 기존과 동일. 단 H1·H2는 양측이므로 구간이 0을 제외하면
  부호에 따라 `SIGNIFICANT_EDGE`(UN이 낫다) / `SIGNIFICANT_NEGATIVE`(J가 낫다)로 읽는다

### 미리 적는 예상

1. **H1·H2는 `UNDERPOWERED`일 가능성이 가장 크다**(추정). f 상관이 +0.94이고
   두 기준의 게이트 통과 집단이 크게 겹칠 것이므로, 차이 계열의 평균은 0에
   가깝고 표본은 390일뿐이다
2. **H4·H6은 음수일 가능성이 크다**(추정). TRUECVD 전 구간에서 지수 대비가
   −0.436%p / −0.482%p로 유의 음수였다. 기준을 바꿔도 그 구조가 바뀔 이유가 없다
3. **H3·H5는 `UNDERPOWERED`**(추정). 전 구간 H1이 ±0.024%p 구간으로
   0과 구별되지 않았고, 이 창은 MDE가 3.2배 크다
4. **게이트 통과 집단의 겹침은 80% 이상**일 것(추정). 부호 불일치 10.9%는
   흐름 수준의 통계이고, 가속(차분)은 §5.2에서 편향이 사라졌던 전례가 있다

### 보조 결과 (서술용 — 판정에 쓰지 않는다)

- `accel(f_J)`·`v15daily(f_J)`의 **NXT 창 단독** 성적(유니버스·지수 대비).
  TRUECVD의 부분기간이므로 **탐색**이다
- h=5의 같은 여섯 계열
- 두 기준의 **게이트 일치율**(둘 다 통과 / 하나만 통과), 통과율, 날짜당 종목 수
- 두 기준의 **상위 15종목 겹침**(점수 순), 회전율
- NXT 비중 분포(종목별·날짜별), NX 결측률, `NX` 전부 0인 종목 수
- 흐름 수준 재측정: `f_J` vs `f_UN` 상관·부호 불일치를 **전 종목·전 NXT 창**에서
  (§0의 900쌍 표본을 모집단 전체로 확장)
- 선행성 지표(신호 전 D−10→D 상승폭, 상승 종목 비율) 기준별

### 하지 않을 것

1. 결과를 보고 창(3+7)·과열상한·매수우위일 문턱·h·신호 시작 규칙을 바꾸지 않는다
2. 보조(h=5, 하위기간, `f_J` 단독)에서 좋은 칸을 주 결과로 올리지 않는다
3. NX 결측 처리를 바꿔 다시 돌리지 않는다(§1.1에 하나로 고정)
4. `UN`을 "`market_div=UN`으로 재수집"해서 쓰지 않는다 — `J + NX` 합으로 만든다
   (§8에서 `UN = J + NX`가 잔차 0으로 확인됐고, 재수집하면 분해 비결정성이
   한 겹 더 들어온다)
5. **일봉(거래량·종가·OBV·MA20)을 통합 기준으로 바꾸지 않는다.** 그것은
   `bars-1.0` 전체를 건드리는 별도 작업이고, 이 사전등록의 질문이 아니다
6. 세 번째 기준(`NX` 단독)으로 게이트를 돌리지 않는다 — NXT 단독 흐름은
   일봉(KRX 기준)과 짝이 맞지 않는다

## §4 무엇이 나오면 무엇을 하나

| 결과 | 행동 |
|---|---|
| H1·H2 둘 다 `UNDERPOWERED` 또는 `NO_SIGNIFICANT_EDGE` | **기준을 바꾸지 않는다.** `J`를 유지하고, 이유를 대비검토 §8.7에 측정값으로 보강한다. NX 테이블은 **참고용으로 보관**한다 |
| H1 또는 H2가 `SIGNIFICANT_EDGE`(UN이 낫다) | 그래도 **이번에 스캐너를 바꾸지 않는다.** 이유: 16.4년 중 10%만 통합 기준이라 패널 일관성이 깨진다(§1.2). 대신 `--basis UN` 옵션을 **참고 열**로 남기고, 2026-10-19 이후 전향 기록을 60거래일 쌓아 다시 판단한다 |
| H1 또는 H2가 `SIGNIFICANT_NEGATIVE`(J가 낫다) | `J` 유지를 **측정 근거로** 확정하고 대장·리포트에 적는다 |
| H3~H6 중 무엇이든 유의 양수 | 기준 질문과 별개의 발견이므로 **새 사전등록**으로 따로 검증한다. 390거래일 부분기간 결과로 스캐너를 바꾸지 않는다 |
| H4·H6이 유의 음수 | TRUECVD의 재현으로 기록한다(새 발견이 아니다) |

**어느 경우든** `tools/kiwoom_cvd_obv_scanner.py`(V1.5, 해시 동결)는 고치지 않는다.
`tools/cvd_accel_truecvd_scan.py`의 기본 기준은 **`J`로 둔다** — `--basis UN`은
선택 옵션으로만 추가하고, 출력 JSON에 기준을 적는다.
