## §1 정의

### 1.1 패널

`cvd_selection.research.features.build_panel(start, end, warmup_start)`을 그대로 쓴다.
10/25 탐색과 **같은 함수**다 — 정의가 두 벌 생기지 않게 한다.

| 항목 | 정의 (`features.py` 문서 문자열과 같다) |
|---|---|
| 일봉 | `read_standard_daily`(bars-1.0, 정규장·수정주가, `drop_failed`, `fill_traded_value`) |
| 체결량 | `cvd_obv.sides_flow.read_sides_flow`(sides-1.0) — 이 기간은 전부 `J`(NXT 개시 전), 확정 행만 |
| 모집단 | `cvd_obv.universe.flat_intervals()` — 신호일 D에 코스피200·코스닥150 편입(이력) |
| DR_n | 100 × Σ(B−S) / Σ(B+S), **D-n .. D-1**(스캐너와 같다 — 당일 흐름은 쓰지 않는다). 창 안에 결측이 하나라도 있으면 NaN |
| POS5 | D-5..D-1 중 B−S > 0인 날 수 |
| Δ(D-1) > 0 | D-1의 B−S > 0 |
| RVOL | V_D / 평균(V_{D-20..D-1}) — **일봉 거래량**(블록딜 포함) |
| AVG_A20 | 평균(거래대금_{D-20..D-1}) |
| 추세 | C > MA20 > MA60, MA20 > MA20(D-5) |
| CLV | (2C − H − L) / (H − L), H = L이면 NaN(불통과) |
| ATRP14 | 100 × Wilder ATR14(D-1까지) / C_{D-1} |

**지금 스캐너와 다른 점(미리 적는다):**
- 지금 스캐너(`cvd_selection/selection.py`)는 RVOL·AVG_A20을 **1분봉 범위**(블록딜 제외)로 계산한다.
  이 기간에는 1분봉이 없어 일봉 거래량을 쓴다. 10/25 탐색과 같은 차이다.
- 1분봉 조건(0 < GAPVWAP ≤ 5%, Rlate ≥ 0, HoldClose ≥ −0.5%)은 넣지 못한다.
  아래 "명세"는 **일봉으로 재현 가능한 명세 조건**이다.

### 1.2 네 집합 — 바꾸는 조건 말고는 전부 같다

공통 조건: AVG_A20 ≥ 100억, DR5 ≥ 5, POS5 ≥ 3, DR2 > 0, Δ(D-1) > 0, RVOL ≥ 1.3, CLV ≥ 0.7.

| 집합 | 추세 | ATRP14 | 흐름 |
|---|---|---|---|
| **S0 명세** | C > MA20 > MA60 · MA20↑ | ≤ 4 | 명세(위 공통) |
| **S1 추세 완화** | **C > MA60 · MA20↑** | ≤ 4 | 명세 |
| **S3 ATRP 완화** | C > MA20 > MA60 · MA20↑ | **상한 없음** | 명세 |
| **S2 흐름 개선(단독)** | 없음 | 없음 | **DR5 − DR20 ≥ 10** 그리고 AVG_A20 ≥ 100억 **만** |

- C > MA20 > MA60이면 C > MA60이므로 **S0 ⊂ S1**이다. 또 **S0 ⊂ S3**다.
  그래서 S1·S3의 질문은 "늘어난 신호(S1 \ S0, S3 \ S0)가 명세 신호보다 나은가"와 같다.
  (S1 평균 − S0 평균 = 늘어난 비중 × (늘어난 신호 평균 − S0 평균) — 부호가 같다)
- S2는 10/25 탐색 격자의 "ΔDR≥10 · 추세 없음 · RVOL 없음 · CLV 없음 · ATRP 없음"과 같다.
  다른 명세 조건을 얹지 않는다. 얹은 형태는 탐색에서 엇갈렸다(§0 (나)는 단독만 적었다).

## §3 가설과 검정

### 주가설 4개 (이 가족 안에서 BH-FDR)

| # | 가설 | 통계 (h=20) | 예측 |
|---|---|---|---|
| **H1** | 추세 완화로 늘어난 신호가 명세 신호보다 낫다 | 신호 단위 두 집단 차이: mean(S1\S0의 초과) − mean(S0의 초과) | > 0 |
| **H2** | 흐름 개선 단독이 유니버스를 이긴다 | 신호일 계열: 날짜별 mean(S2 순수익) − mean(그날 유니버스 순수익) | > 0 |
| **H3** | ATRP 상한을 풀어 늘어난 신호가 명세 신호와 **다르다** | 신호 단위 두 집단 차이: mean(S3\S0의 초과) − mean(S0의 초과) | **양측**(방향 예측 없음) |
| **H4** | 흐름 개선 단독이 지수를 이긴다 | 신호일 계열: 날짜별 mean(S2 순수익) − KOSPI200 h20 수익 | > 0 |

- "초과" = 그 종목 h20 순수익 − 같은 날 편입 종목 전체 평균 순수익(비용은 양쪽 같아 상쇄).
  두 집단 차이에서 유니버스는 상쇄되지만 날짜 구성이 다르므로 초과로 맞춘다.
- H1·H3 통계: `tools/ab_backtest_negfilter.summarize_diff(e, is_ex, clusters, reps, seed)`.
  `is_ex` = 늘어난 신호, `clusters` = **신호일의 달력 분기**. 재표본 4000, 시드 **20261025**.
- H2·H4 통계: `tools/ab_backtest_b.summarize(x, block=20, reps=4000, seed=20261025)`.
  신호일 계열 **이동 블록 부트스트랩**, 블록 = 보유기간 20.
- 구간은 부트스트랩 2.5/97.5 백분위다. MDE = 2.8 × SE. q값은 **4개 p값에 BH-FDR**(`ab_backtest_b.bh_fdr`)로 낸다.
- 판정은 H2·H4가 `ab_backtest_b.verdict`, H1·H3가 같은 규칙을 차이에 적용한 것이다(아래).
- 신호 단위 차이의 판정:
  - 구간 > 0 · q ≤ 0.05이면 `SIGNIFICANT_EDGE`(늘어난 신호가 낫다).
  - 구간 < 0이면 `SIGNIFICANT_NEGATIVE`(명세 신호가 낫다).
  - 0 포함이고 |관측| < MDE면 `UNDERPOWERED`, 아니면 `NO_SIGNIFICANT_EDGE`.
  - H3은 양측이므로 구간 > 0이면 q ≤ 0.05일 때 `SIGNIFICANT_EDGE`, 구간 < 0이면 `SIGNIFICANT_NEGATIVE`로 읽는다.
- 집단 하나라도 신호가 10건 미만이면 `INSUFFICIENT`다.

### 미리 적는 예상

1. **H1·H3는 `UNDERPOWERED`일 가능성이 크다**(추정).
   - 2022 ~ 2024에 S0이 3년 292건, 늘어난 신호가 S1 118건·S3 76건이었다.
   - 이 비율이면 11.4년에 S0 약 1,100건, 늘어난 신호 수백 건이다. 차이의 SE는 약 1%p, MDE는 약 2.5 ~ 3%p로 본다.
   - 탐색의 차이(검증 +1.4%p 안팎)는 그보다 작다. 2010년대 초에는 AVG_A20 100억 때문에 신호가 더 적을 것이다.
2. **H2는 작은 양수이고, 유의할 수도 있다**(추정).
   - 신호가 수만 건이라 MDE가 0.3 ~ 0.4%p 수준으로 본다.
   - 다만 탐색에서 연도별 부호가 바뀌었다(2023·2026 음수). 오분위 효과도 학습 +0.55 → 검증 +0.08%p로 줄었다.
   - **격자 756개에서 고른 값이므로** 실제 효과는 탐색값(+0.38 ~ +1.03%p)보다 작을 것이다.
3. **H4는 `SIGNIFICANT_NEGATIVE` 또는 `UNDERPOWERED`**(추정). 대장 공통 교훈 1(동일가중 유니버스가 16년간 KOSPI200에 뒤졌다)과 8·10번의 지수 대비 결과가 근거다.
4. **어느 것이 유의해도 "발견"이 아니다.** 작성일 이후 데이터로 확인할 후보다.

### 보조 결과 (서술용 — 판정에 쓰지 않는다)

- 집합별 h20 초과·순수익·승률: S0, S1, S3, S2, 그리고 **S1과 S3을 함께 푼 집합**(추세 완화 + ATRP 상한 없음).
- h=5·60의 같은 네 계열.
- 하위기간 2010-07 ~ 2015-12 / 2016-01 ~ 2021-11의 부호 안정성.
- S2의 DR5 − DR20 오분위별 h20 초과(단조성).
- 늘어난 신호의 성격: S1\S0의 C/MA20, S3\S0의 ATRP14 분포와 −5%/+8% 먼저 닿는 비율(매매 규칙 연결용, 판정 없음).
- 신호 수·날짜 수·종목 수, 연도별 신호 수.
- 전향 기록: 2026-10-26 이후 `cvd_selection.scan` 결과(`cvd_selection/output/`)에 S0~S3 통과 여부를 함께 남긴다. 표본이 쌓일 때까지 판정하지 않는다.

### 하지 않을 것

1. 결과를 보고 임계값을 바꾸지 않는다(ΔDR 10 → 5·15, ATRP 4 → 6·8, 추세 정의 등). **다른 값을 보고 싶으면 새 사전등록이다.**
2. 주 검정 기간에 2022-01 이후를 넣지 않는다. 신호 시작·끝을 결과를 보고 옮기지 않는다.
3. 보조(h=5·60, 하위기간, S1+S3 결합)에서 좋은 칸을 주 결과로 올리지 않는다.
4. S2에 명세 조건을 얹거나 빼서 다시 돌리지 않는다.
5. 1분봉 조건을 대신할 일봉 근사를 만들어 넣지 않는다.
6. `features.build_panel`의 정의를 이 검정을 위해 고치지 않는다. 버그를 고치면 **결과를 보기 전인지 후인지** 리포트에 적고, 10/25 탐색도 다시 돌려 바뀐 값을 적는다.

## §4 무엇이 나오면 무엇을 하나

| 결과 | 행동 |
|---|---|
| H1 `SIGNIFICANT_EDGE` | 스캐너 추세 조건을 C > MA60 · MA20↑로 바꾸는 안을 **사용자에게 보고하고 결정을 받는다.** 바꾸면 `DESIGN_VERSION`을 올리고, 스캐너 판정이 백테스트 S1 판정과 같다는 테스트를 붙인다. 지수 대비는 이 가설에 없으므로 "명세 안에서 나은 선택"이라고 적는다 |
| H3 `SIGNIFICANT_EDGE` | 위와 같다(ATRP 상한 제거). `SIGNIFICANT_NEGATIVE`면 4% 유지 근거로 기록한다 |
| H1·H3 `UNDERPOWERED` / `NO_SIGNIFICANT_EDGE` | 명세 조건을 **유지**한다. 필요한 표본 수(MDE가 관측 차이 아래로 내려가는 신호 수)를 리포트에 적는다. 상승 초기 포착(10/25 탐색 1부)을 목표로 바꿀지는 수익 근거와 별개인 **사용자 결정**이다 |
| H2 `SIGNIFICANT_EDGE`이고 H4가 음수·불가 | "유니버스 안에서 나은 흐름 조건"으로만 기록한다. 스캐너에는 **보조 표시**(점수 아님)로 DR5 − DR20을 출력하는 것까지만 제안한다 |
| H2·H4 둘 다 `SIGNIFICANT_EDGE` | 스캐너 흐름 조건에 넣는 안을 사용자에게 보고한다. 전향 기록으로 확인한 뒤 바꾼다 |
| H2 `UNDERPOWERED` / 음수 | 10/25 탐색의 ΔDR 결과를 **학습 구간 과적합**으로 기록한다 |

**어느 경우든:**
- `tools/kiwoom_cvd_obv_scanner.py`(V1.5, 해시 동결)는 고치지 않는다.
- 스캐너 조건은 이 리포트와 사용자 결정 없이 바꾸지 않는다.

**구현 메모 (본질 아님, 실행 전 확인할 것):**
- `cvd_selection/research/`는 `.gitignore`의 `research/` 규칙에 걸려 git에서 무시된다. 재현 기록을 남기려면 실행 전에 규칙이나 경로를 정리한다. 경로를 바꾸면 리포트에 적는다.

이 문서는 확정됐다. 실행 전 비본질적 수정(경로·오타)만 허용하고 리포트에 적는다.
