**보지 않은 것 — 중요**: 이 가족에서 **수익률을 한 번도 보지 않았다.** 위는
전부 *신호끼리의 일치도*이고, 전진 수익·초과수익·승률은 계산하지 않았다.
그래서 아래 주가설(전부 수익 기준)은 **엿보지 않은 상태**다.

**그러나 설계는 엿본 데이터에서 왔다**: `accel-1.0`의 창(3+7)·과열상한(10%)은
D3(1분봉 250거래일)에서 조정됐고, `V1.5`의 임계값은 전부 "검증 전 초기
설계값"이다(코드 docstring). 즉 **게이트 자체가 다른 데이터에서 만들어진
것이므로, D4에서 좋게 나와도 그 게이트를 고른 과정이 무작위가 아니다.**

**대장 상태**: 사전등록 7개, 주가설 20개(실질 18). 이것이 8번째이고 새 가족이다.

## §1 정의

### 1.1 흐름 — f_true

```
f_true(d) = (buy_qty(d) − sell_qty(d)) / (buy_qty(d) + sell_qty(d))
```

- 원천: `silver.daily_trade_sides`(KIS FHKST03010800, `market_div="J"`),
  reader는 `cvd_obv.ingestion.kis_trade_sides.read_trade_sides()`
- **`buy_qty + sell_qty`를 거래량으로 쓰지 않는다.** 정규장 거래량의 92~96%다
  (§0). 흐름은 자기 합으로 정규화되므로 영향이 없다
- `quality_flags`에 `TRADE_SIDE_BOTH_ZERO`가 있는 행은 **흐름이 없는 날**로
  본다(0으로 채우지 않는다)

### 1.2 설계 A — `accel(f_true)`

`tools/cvd_accel_scanner.py`의 accel-1.0 게이트 5개에서 `f`만 바꾼다.

```
최근 = mean(f_true, D−2…D) 3거래일 · 이전 = mean(f_true, D−9…D−3) 7거래일
가속 A = 최근 − 이전
게이트 ① f_true가 D−9…D 10거래일 연속 존재  ② A > 0  ③ 최근 > 0
       ④ 20일 평균 거래대금 존재  ⑤ 종가 ≤ MA20 × 1.10
```

구현은 `tools/accel_vidya_backtest.py`의 `accel_from_flow`·`rolling_mean`을
**import**해서 쓴다(가속 정의가 두 벌 생기지 않게).

### 1.3 설계 B — `v15daily(f_true)`

V1.5(`tools/kiwoom_cvd_obv_scanner.py::_compute_gate`)의 정규장 절대조건 중
**일별 데이터로 재현 가능한 5개**만 쓴다.

| V1.5 조건 | 일별 재현 | 이 설계에서 |
|---|---|---|
| `normalized_delta > 0` | 가능 — 창 전체 Σ(buy−sell)/Σ(buy+sell) | **쓴다** |
| `정규장 매수우위일 비율 ≥ 50%` | 가능 — 창 안 `f_true > 0`인 날의 비율 | **쓴다** |
| `종가 > MA20` | 가능 | **쓴다** |
| `OBV 정규화기울기 > 0` **그리고** `OBV > OBV MA20` | 가능(일봉 기반) | **쓴다** |
| 유동성(20일 평균 거래대금) 존재 | 가능 | **쓴다** |
| **`normalized_momentum > 0`**(30분 구간) | **불가 — 장중 필요** | **뺀다** |

창은 V1.5 기본과 같은 **최근 10거래일**로 둔다. OBV·MA20·유동성은
`tools/ab_backtest_b.load_all_bars`(기준 일봉)로 계산하고, OBV 정의는 V1.5
`calc_obv`를 import해 쓴다.

> **이것은 V1.5가 아니다.** 모멘텀 조건을 뺐으므로 더 느슨한 게이트이고,
> 지금까지의 V1.5 결과를 물려받지 못한다. 리포트에 항상 `v15daily`로 적는다.

### 1.4 모집단·유니버스

`cvd_obv.universe.membership_intervals()`(이력만) — 과거 구성종목 797종목.
현재 명단만 쓰면 생존 편향이 들어간다.

## §3 가설과 검정

### 주가설 4개 (이 가족 안에서 BH-FDR)

| # | 가설 | 계열 (h=2) | 예측 |
|---|---|---|---|
| **H1** | `accel(f_true)`가 유니버스를 이긴다 | 날짜별 `mean(통과) − mean(그날 유니버스)` | > 0 |
| **H2** | `accel(f_true)`가 지수를 이긴다 | 날짜별 `mean(통과) − KOSPI200 수익` | > 0 |
| **H3** | `v15daily(f_true)`가 유니버스를 이긴다 | 〃 | > 0 |
| **H4** | `v15daily(f_true)`가 지수를 이긴다 | 〃 | > 0 |

- 짝짓는 이유: 신호가 많이 나는 날은 시장이 오르는 날이다
- 통계: 신호일 계열 **이동 블록 부트스트랩**, 블록 = 보유기간 = 2,
  재표본 4000, 시드 **20261019**. 구간은 부트스트랩 2.5/97.5 백분위
- MDE = 2.8 × SE. q값은 4개 p값에 BH-FDR
- 판정 규칙은 기존 사전등록과 동일(`SIGNIFICANT_EDGE` / `SIGNIFICANT_NEGATIVE`
  / `UNDERPOWERED` / `NO_SIGNIFICANT_EDGE`)

### 미리 적는 예상

1. **H1은 양수이나 유의하지 않을 가능성이 가장 크다**(추정). D3 250일에서
   `accel(f_est)` − 유니버스가 +0.051%p [−0.045, +0.147]였다. 표본이 16배
   늘면 SE가 1/4로 줄어 MDE ≈ 0.035%가 되므로, 효과가 그 전후면 유의가 갈린다
2. **H2·H4는 `UNDERPOWERED` 또는 음수**(추정). B 사전등록의 교훈 — 동일가중
   유니버스가 16년간 지수에 크게 뒤졌다
3. **H3는 H1보다 나쁠 것**(추정). `v15daily`는 `종가>MA20`·`OBV>MA20`을
   요구하는 수준(level) 설계이고, 그 성질이 D1·D3에서 불리하게 측정됐다
4. `accel(f_true)` 통과율은 D4 표본에서 본 30.6% 근처일 것

### 보조 결과 (서술용 — 판정에 쓰지 않는다)

- h=5 같은 네 계열
- 하위기간 2010-2018 / 2018-2026 (부호 안정성)
- **선행성 지표** 집단별 신호 전 상승폭 D−10→D, 상승 종목 비율
- 겹치는 1분봉 구간(2025-09-12~2026-09-22)에서 `accel(f_est)` 대조 — 같은
  창·같은 게이트로 두 원천을 짝지은 차이
- 커버리지(통과율·날짜당 종목 수), 회전율
- 상위 5종목 동일가중 h=2 단순 회전(청산 엔진 아님)

### 하지 않을 것

1. 결과를 보고 창(3+7)·과열상한·매수우위일 문턱(50%)·h를 바꾸지 않는다
2. 하위기간·h=5 중 좋은 칸을 주 결과로 올리지 않는다
3. `v15daily`에 30분 모멘텀을 **다른 것으로 대체해 넣지 않는다**(장중 데이터가 없다)
4. 두 설계를 합친 조건(A ∩ B)을 주가설로 추가하지 않는다
5. `market_div`를 섞지 않는다(`J`만)

## §4 무엇이 나오면 무엇을 하나

| 결과 | 행동 |
|---|---|
| H1이 `SIGNIFICANT_EDGE` **그리고** 선행성 유지(신호 전 상승폭 ≤ +5%) | `accel-2.0` 후보로 올린다. 스캐너에 **참고 열**로 f_true를 추가하고(게이트 변경 아님) 2026-10-19 이후 전향 기록을 60거래일 쌓은 뒤 다시 판단한다 |
| H1 유의하나 선행성이 깨짐(> +5%) | 스캐너를 바꾸지 않는다. "수익은 오르나 설계 목적과 상충"으로 기록하고 사용자 판단 사항으로 올린다 |
| H3만 유의 | 수준 설계가 체결량에서는 작동한다는 뜻 — **새 사전등록**으로 따로 검증한다. 이 결과만으로 V1.5를 바꾸지 않는다(모멘텀 조건을 뺀 게이트다) |
| 전부 `UNDERPOWERED` | 스캐너를 바꾸지 않는다. 필요한 표본 수를 기록한다 |
| `SIGNIFICANT_NEGATIVE` | 그 설계를 후보에서 제외하고 기록한다 |

**어느 경우든 V1.5 파일(`tools/kiwoom_cvd_obv_scanner.py`)은 고치지 않는다** —
해시 동결 대상이다.
