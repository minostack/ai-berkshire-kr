# 스캐너 팀: 5개 스캐너 병렬 실행 + 취합 보고

스캐너 5종을 **5개 에이전트가 동시에** 돌리고, 5개가 모두 끝나면 **취합 에이전트**가
결과를 한 장의 보고서로 묶습니다.

| 역할 | 담당 스킬 | 정의 파일 |
|---|---|---|
| **scan-lead** (본인) | 에이전트 실행·대기·취합 에이전트 실행·최종 전달 | 이 파일 |
| **cvdsel-agent** | `/cvd-selection-scan` | `skills/cvd-selection-scan.md` |
| **accel-agent** | `/cvd-accel-scan` | `skills/cvd-accel-scan.md` |
| **closing-agent** | `/closing-bet-scan` | `skills/closing-bet-scan.md` |
| **ab-agent** | `/ab-candidate-scan` | `skills/ab-candidate-scan.md` |
| **daily-agent** | `/daily-scanner` | `skills/daily-scanner.md` |
| **report-agent** | 5개 결과 취합·교차 분석·보고서 저장 | 이 파일 3단계 |

**지원 입력 형식**:

```
/scan-team                         # 5종 모두 기본값으로 실행
/scan-team date 2026-11-19         # 기준일 지정 (날짜를 받는 스캐너에만 전달)
/scan-team live                    # closing-bet-scan만 live 모드 (15:20 전후 종가매수용)
/scan-team skip daily-scanner      # 일부 제외 (쉼표 구분 가능)
/scan-team only cvd-selection-scan,ab-candidate-scan   # 일부만
```

인자는 조합할 수 있습니다(예: `/scan-team date 2026-11-19 skip daily-scanner`).

**이 스킬은 데이터를 적재하지 않습니다.** 각 스캐너와 마찬가지로 기적재분만 읽습니다.
`data-load`·`update_index`·`universe refresh`는 어느 에이전트도 실행하지 않습니다
(5개가 동시에 쓰면 저장소가 깨질 수 있음). 데이터가 낡았으면 경고로만 보고합니다.

---

## 실행 절차

### 0단계: 인자 해석과 기준일

1. `$ARGUMENTS`를 해석해 실행할 스캐너 목록과 스캐너별 인자를 정합니다.

| 팀 인자 | cvd-selection-scan | cvd-accel-scan | closing-bet-scan | ab-candidate-scan | daily-scanner |
|---|---|---|---|---|---|
| (없음) | 기본 | 기본 | 기본 | 기본 | 기본 |
| `date D` | `date D` | 해당 없음 → 경고 | `date D` | `date D` | 해당 없음 → 경고 |
| `live` | — | — | `live` | — | — |

   날짜를 받지 않는 스캐너(accel·daily)는 **최신 데이터 기준**으로 돌고, 기준일이
   다르다는 사실을 취합 보고서에 남깁니다.

2. 실행 시각(`YYYYMMDD_HHMMSS`)과 결과 폴더를 정합니다:
   `reports/daily-scan/scan-team-{YYYYMMDD}-{HHMMSS}/` (실행마다 새 폴더).

### 1단계: 스캐너 에이전트 5개 동시 실행

**한 메시지 안에서 Agent 도구를 5번 호출**해 병렬로 띄웁니다
(`subagent_type: "general-purpose"`, `run_in_background`는 쓰지 않음 — 결과를 기다려야
취합할 수 있음). 각 에이전트에 아래 프롬프트를 `{}`만 바꿔 넘깁니다.

```
너는 {역할} 이다. 작업 디렉토리 C:\A-AI\ai-berkshire-kr 에서
skills/{스킬}.md 를 끝까지 읽고, 그 '실행 절차'를 인자 "{인자}" 로 그대로 수행하라.

규칙:
- 데이터를 적재·갱신하지 마라: data-load, cvdobv.py data-load, tools/update_index.py,
  universe refresh, minute-collect 를 실행하지 않는다. 다른 에이전트 4개가 같은
  저장소를 동시에 읽고 있다. 스킬이 '스캔 전 갱신'을 권하면 하지 말고 경고로만 남긴다.
- 스킬에 정의된 판정 임계값을 바꾸지 마라.
- 다른 스킬·스캐너를 부르지 마라. 사용자에게 질문하지 마라(기본값으로 진행).
- 명령이 실패하면 한 번만 원인을 확인하고, 고칠 수 없으면 실패로 보고한다.
  코드를 수정하지 않는다.
- 스킬이 정한 저장 위치에 결과를 저장한다(스킬 기본 동작 그대로).
- 아래 형식의 결과 파일을 {결과폴더}/{번호}-{스킬}.md 에 쓴다.

결과 파일 형식 (한국어):
# {스킬} 결과
- 상태: 성공 / 부분 성공 / 실패
- 실행 명령: (실제로 돌린 명령 그대로)
- 기준일·데이터 기준: (스캐너가 출력한 [데이터 기준]·잠정/확정 여부·경고 그대로)
- 평가 종목 수 / 통과 종목 수
- 검증 상태 경고: (스킬 문서의 '검증 상태'·'주의사항' 중 핵심 1~3줄)
## 후보
| 순위 | 종목코드 | 종목명 | 유형/신호 | 점수·핵심 수치 | 비고 |
## 경고·실패 사유
## 스캐너 원본 저장 파일 경로

마지막 응답으로 결과 파일 경로와 '상태 / 통과 종목 수 / 상위 종목코드 목록'
한 줄만 돌려준다.
```

| 번호 | 역할 | 스킬 |
|---|---|---|
| 1 | cvdsel-agent | cvd-selection-scan |
| 2 | accel-agent | cvd-accel-scan |
| 3 | closing-agent | closing-bet-scan |
| 4 | ab-agent | ab-candidate-scan |
| 5 | daily-agent | daily-scanner |

daily-agent에는 추가로 다음을 붙입니다: "daily-scanner의 5단계 뉴스 교차 확인은
핵심 후보 상위 5종목까지만 한다."

### 2단계: 5개 종료 대기 → 결과 확인

5개 에이전트가 **모두** 돌아올 때까지 기다립니다. 돌아온 뒤:

- 결과 파일 5개가 실제로 있는지 확인합니다. 없거나 실패면 실패로 기록하고 **재실행하지
  않습니다**(재실행 여부는 사용자가 결정).
- 에이전트 요약은 보고일 뿐이므로, 결과 파일 내용을 기준으로 삼습니다.

### 3단계: 취합 에이전트 실행

Agent 도구로 **report-agent** 하나를 띄웁니다(`general-purpose`). 프롬프트:

```
너는 report-agent 다. 작업 디렉토리 C:\A-AI\ai-berkshire-kr.
{결과폴더} 의 01~05 결과 파일을 모두 읽고 (필요하면 각 파일에 적힌 스캐너 원본
저장 파일도 읽고) {결과폴더}/취합리포트.md 를 한국어로 써라.
새 스캔·데이터 적재·웹 검색은 하지 않는다. 결과 파일에 없는 수치를 만들지 않는다.

CLAUDE.md '투자 리서치 핵심 원칙'을 지킨다: 사실과 의견(추정) 구분, 주관 표현 금지,
불확실하면 '데이터 부족'으로 적는다. 매수 권유 문구를 쓰지 않는다.

보고서 구성:
1. 실행 개요 — 실행 시각, 스캐너별 상태(성공/부분/실패), 기준일·잠정/확정 여부.
   스캐너 간 기준일이 다르면 표로 명시.
2. 데이터 경고 — 스캐너들이 낸 [데이터 기준]·낡은 데이터·누락 종목 경고 모음.
3. 스캐너별 요약 표 — 스캐너 | 평가 수 | 통과 수 | 상위 후보(최대 5) | 검증 상태.
4. 교차 출현 종목 — 2개 이상 스캐너에 나온 종목. 종목코드 | 종목명 | 출현 스캐너 수 |
   출현 스캐너와 각 신호. 출현 수 내림차순. 없으면 '없음'.
   (주의 문구 필수: 스캐너들은 같은 일봉·거래량에서 나온 신호라 서로 독립이 아니며,
   교차 출현이 수익 우위를 뜻한다는 검증은 없다.)
5. 스캐너별 전체 후보 — 각 결과 파일의 후보 표를 그대로 옮긴다.
6. 검증 상태 한눈에 — 각 스킬 문서의 검증 상태(유의/미확립/판정 불가 등)를 한 줄씩.
7. 원본 파일 경로 목록.

마지막 응답으로 보고서 경로와 '교차 출현 상위 종목 최대 5개' 한 줄만 돌려준다.
```

### 4단계: 사용자에게 전달

`취합리포트.md`를 읽고 사용자에게 다음을 보여줍니다(보고서 전체를 붙이지 않음):

1. 스캐너별 상태·통과 수 (한 표)
2. 데이터 경고 (있으면 맨 앞)
3. 교차 출현 종목 상위
4. 보고서 경로 링크

---

## 주의사항

1. **5개 스캐너 모두 단독 매매 근거로 검증되지 않았습니다.** 각 스킬 문서의
   '검증 상태'·'주의사항'을 그대로 따릅니다. 교차 출현도 검증된 신호가 아닙니다.
2. **동시 실행 부하**: ab-agent(DART)·closing-agent(시장 최신 거래일 조회)·daily-agent(KIS)가
   외부 API를 부를 수 있습니다. 호출 제한 오류가 나면 해당 에이전트는 실패로 보고되고,
   사용자가 그 스캐너만 다시 돌리면 됩니다(예: `/closing-bet-scan`).
3. 결과 폴더 `reports/daily-scan/scan-team-*/`는 중간 산출물입니다. GitHub 푸시는
   사용자가 결정합니다.
4. 스캐너 정의가 바뀌면 이 스킬은 고칠 필요 없이 각 스킬 파일을 다시 읽어 따릅니다.
