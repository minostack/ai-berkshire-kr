# 기업 뉴스 펄스: 주가 급변 원인 규명 팀

$ARGUMENTS 에 대해 최근 뉴스 정찰과 급변 원인 규명을 수행합니다. **이것은 심층 리서치가 아니라 정보 신속 대응입니다** — 목표는 10분 안에 "이 기업에 최근 무슨 일이 있었나? 주가 급변의 진짜 원인은 무엇인가? 투자 논거를 재검토해야 하나?"에 답하는 것입니다.

## 적용 상황

- 보유/관심 종목의 주가 급등·급락 (일반 기준선: 하루 ±5%, 일주일 ±10%)
- 실적 발표 후 주가 급변, 시장이 무엇에 반응하는지 빠르게 파악하고 싶을 때
- 뉴스 헤드라인을 봤지만 노이즈인지 진짜 신호인지 확신이 없을 때
- **적용하지 않음**: 종합 리서치(`/investment-team`), 실적 정밀 분석(`/earnings-review`), 장기 논거 추적(`/thesis-tracker`)

## 실행 절차

### 1단계: 파라미터와 상황 확인

다음 정보를 사용자에게 확인합니다($ARGUMENTS에 없을 경우):

| 파라미터 | 설명 | 기본값 |
|------|------|------|
| **기업명** | 한글/영문/종목코드 모두 가능 | 필수 |
| **기간** | 뉴스를 거슬러 볼 일수 | 기본 14일, 실적 시즌에는 7일로 단축 가능 |
| **주가 급변** | 등락폭 + 기간, 예: "12% 하락/3일" | 선택, 있으면 원인 규명 초점에 사용 |
| **중점 영역** | 기업 이벤트 / 규제 / 산업 / 심리 | 기본은 4개 영역 균등 |

사용자가 기업명만 말했다면 먼저 되묻습니다: "최근 며칠간의 뉴스를 볼까요? 설명이 필요한 구체적인 주가 급변이 있나요?" — **조용히 가정하지 마십시오**.

### 2단계: 정보 가용성 등급

`investment-team.md`의 A/B/C 등급을 참고하되, 기준은 다릅니다:

| 등급 | 특징 | 정찰 전략 |
|------|------|---------|
| **A등급 (정보 풍부)** | 대형주, 언론 노출 많음, 실적 시즌 | 핵심은 **노이즈 제거와 원인 규명** — 정보가 너무 많으면 오히려 진짜 원인을 찾기 어렵다. 각 Agent는 판단력을 갖고 "반복 전재"된 2차 뉴스를 걸러내야 한다 |
| **B등급 (정보 보통)** | 중소형주, 노출 보통 | 표준 모드, 핵심 이벤트마다 독립 출처 1~2개 첨부 |
| **C등급 (정보 부족)** | 코스닥 소형주·홍콩 소형주, 신규 상장, 비인기 종목 | "기초 조사 모드"로 전환 — 급변을 설명할 뉴스를 전혀 못 찾을 수도 있으며, **그 결론 자체가 가치 있다** (펀더멘털이 아닌 기술적/수급 요인일 수 있음) |

등급을 각 Agent에게 알려 정찰 방식에 반영하게 합니다.

### 3단계: 팀 생성

TeamCreate로 팀 생성:
- `team_name`: `{기업명}-newspulse` (영문 소문자, 예: `pdd-newspulse`, `samsung-newspulse`)
- `agent_type`: `team-lead`

### 4단계: 정찰 과제 4개 생성

TaskCreate로 다음 4개 과제를 생성합니다:

#### 과제 1: 기업 이벤트 정찰 (company-event-scout)

- **subject**: `{기업명} 최근 {N}일 기업 자체 이벤트 정찰`
- **description**:
  1. **공식 공시**: DART/KRX KIND/SEC 등 감독기관 공시 플랫폼의 최근 공시
  2. **실적과 가이던스**: 최신 분기·연간 실적, 잠정실적, 실적 발표회(컨퍼런스콜) 요점
  3. **경영진 동향**: 임원 변동, 지분 매수·매도, 자사주 매입, 배당, 주식보상
  4. **주요 사업 이벤트**: 신제품 출시, 인수합병·구조조정, 사업 매각, 대형 고객/대규모 수주
  5. **자본 거래**: 유상증자, 전환사채(CB)·신주인수권부사채(BW), ADR 전환, 상장폐지·이전상장 논의
  6. **소송과 컴플라이언스**: 피소, 자진 공시한 컴플라이언스 사안
  7. 각 이벤트 표기: **날짜 / 출처 링크 / 한 줄 요약 / 주가 급변과의 관련 가능성(높음/중간/낮음)**
  8. 시간 역순 타임라인 표로 출력

#### 과제 2: 규제와 정책 (regulatory-watcher)

- **subject**: `{산업/기업} 최근 {N}일 규제·정책 변화 정찰`
- **description**:
  1. **산업 규제**: 해당 산업의 신규 규정, 과징금, 시정명령, 인허가 변화
  2. **국가 간 정책**: 미중 관계, 한미 통상, 관세, 수출 통제, 데이터 보안
  3. **세제 정책**: 부가가치세, 법인세, 금융투자소득세·배당소득세 등 관련 변화
  4. **반독점과 경쟁법**: 공정위 조사, 과징금, 기업결합 불허
  5. **특수 산업 정책**: 약가 인하·급여 정책, 부동산 PF·대출 규제, 플랫폼 규제, 원전·방산·에너지 정책 등
  6. **통화와 외환**: 해당 기업에 영향을 주는 환율/금리/자본 통제 변화
  7. 각 정책 표기: **날짜 / 출처 / 해당 기업에 대한 영향 정도(직접/간접/무관)**
  8. 핵심 판단: 방금 현실화된 "정책 블랙스완"이 있는가

#### 과제 3: 산업과 경쟁사 (industry-peer-analyst)

- **subject**: `{기업명} 산업 구도와 경쟁사 최근 {N}일 동향 정찰`
- **description**:
  1. **직접 경쟁사**: 핵심 경쟁사 3~5곳을 나열하고 각각 최근 이벤트 조사 (실적, 제품, 가격 경쟁, 인사)
  2. **밸류체인 전후방**: 상류 원자재/공급사, 하류 고객/채널의 최근 가격·생산능력·수주 변화
  3. **산업 전체**: 업황 데이터, 출하량, 수요 측 신호 (소비 데이터, 입찰 데이터, 수출입 통계 등)
  4. **대체재 위협**: 신기술·새 비즈니스 형태가 해당 산업에 주는 충격
  5. **업종 지수 성과**: 동종 업종 종목의 최근 성과, 해당 기업이 초과/미달/동행 중인지
  6. 핵심 판단: **기업 개별 이벤트인가, 산업 전체의 베타 변동인가?**
  7. 각 이벤트에 출처와 날짜 표기

#### 과제 4: 시장 심리와 증권사/인플루언서 (sentiment-tracker)

- **subject**: `{기업명} 최근 {N}일 시장 심리와 기관 의견 변화 정찰`
- **description**:
  0. **수급 수치 먼저 확보 (한국주)**: 검색 전에 `python tools/kis_flow.py {6자리 종목코드} --from {시작일} --to {오늘}`을 실행해 KIS 수치를 받습니다. 출력의 기간 요약과 일별표를 보고서에 그대로 인용하고 출처는 "KIS REST(tools/kis_flow.py)"로 적습니다. 도구가 실패하면(KIS 키 없음, 조회 실패) 실패 사유를 데이터 공백에 적고 아래 항목을 WebSearch로 대신 찾습니다. 미국·홍콩주는 이 단계를 건너뜁니다
  1. **증권사 투자의견 변동**: 국내 증권사는 kis_flow의 "증권사 투자의견" 표(최근 90일, 날짜·증권사·의견·목표가)로 먼저 확인하고, 외국계(골드만삭스, 모건스탠리 등)와 목표가 상향·하향 여부는 WebSearch로 보완합니다. KIS는 직전 목표가를 주지 않으므로 같은 증권사의 이전 행과 비교해 변화를 적습니다
  2. **기관 보유 변화**: 5% 대량보유 공시(DART), 외국인·기관·개인 순매수와 기관 세부(투신·사모·연기금·보험·은행·증권·기타법인), 프로그램 순매수(kis_flow), 13F 공시(미국주)
  3. **공매도 데이터**: 일별 공매도 수량·거래량 대비 비중과 대차잔고 증감(kis_flow), 새로 발표된 공매도 리포트(있을 경우)
  4. **인플루언서 의견**: 주요 투자자·애널리스트의 관련 최근 발언 (WebSearch로 확인)
  5. **루머와 지라시**: 언론의 미확인 루머, 소셜미디어 화제 (종목토론방/X/Reddit/雪球)
  6. **기술적 신호**: 주요 지지/저항선 도달 여부, 블록딜 여부(뉴스·공시로 확인), 신용융자 잔고·잔고율·신규/상환 변화(kis_flow)
  7. 핵심 판단: **펀더멘털 주도인가, 심리/수급 주도인가?** — kis_flow의 급변일(⚡) 행마다 "그날 누가 팔았나/샀나"(외국인·기관·개인 순매수와 어느 기관 세부 주체가 주도했나, 프로그램 순매수 방향, 공매도 비중이 기간 평균보다 높은가, 대차잔고가 늘었나)를 한 줄로 적고, 같은 날 뉴스와 맞춰 봅니다
  8. **kis_flow 읽을 때 주의**: 당일 행은 장중 잠정이고, 공매도는 익일 공표, 신용잔고는 매매일 기준 T+2 공표라 최근 2거래일이 비어 있습니다. 비어 있는 값을 추정으로 채우지 않습니다. 오늘 투자자별 확정치는 15:40 이후에만 나오며, 장중에는 "장중 가집계"(추정)만 있으니 확정치처럼 인용하지 않습니다. 프로그램 순매수는 외국인·기관 매매와 겹치므로 더하지 않습니다. 기본은 KRX(`--market J`)이며, NXT 거래가 큰 종목은 `--market UN`(통합)으로 한 번 더 확인합니다

### 5단계: Agent 4개 병렬 실행

**반드시 한 메시지에서 Task 도구를 4번 병렬 호출합니다**. 각 Agent 설정:
- `subagent_type`: `general-purpose`
- `run_in_background`: `true`
- `team_name`: `{기업명}-newspulse`
- `name`: 해당 역할명 (company-event-scout / regulatory-watcher / industry-peer-analyst / sentiment-tracker)

각 Agent의 prompt 템플릿:

```
당신은 {기업명} 뉴스 펄스 팀의 "{역할 한글명}"이며, {정찰 영역} 영역의 최근 {N}일 이벤트 정찰을 맡습니다.

기간: {시작일} ~ {오늘 날짜}
주가 급변 배경: {사용자가 제공한 급변 정보, 없으면 "특정 급변 없음, 정기 점검"}
정보 가용성 등급: {A/B/C}

과제 #{과제 번호}를 완료하십시오: {과제 subject}

구체적 정찰 요구사항:
{과제 description 내용}

**정찰 방법**:
- 시의성 있는 검색은 WebSearch 우선 사용 (키워드에 날짜나 "최근", "latest", "2026" 추가)
- 핵심 이벤트는 WebFetch로 원 출처 정독 (공시 원문, 실적 자료, 규제 문서)
- 각 이벤트에 "독립 출처 검증" — 루머는 최소 2개 독립 출처 필요
- **낚시성 제목에 속지 말 것**: 제목과 본문이 다른 이벤트는 "제목 오도"로 표기

**출력 형식 (중요)**:
1. **핵심 발견**: 가장 중요한 이벤트 3~5개, 각 1~2문장
2. **전체 이벤트 타임라인 표** (날짜 역순):
   | 날짜 | 이벤트 | 출처 | 주가 급변과의 관련성 | 지속성 |
3. **본 영역 원인 규명 결론**: 정찰한 이벤트를 바탕으로 "이 영역이 주가 급변을 설명할 수 있는가? 신뢰도는?"에 답변
4. **데이터 공백 선언**: 찾지 못한 정보, 의문점, 추가 정보를 기다려야 할 사항
5. "사실"과 "추정"을 엄격히 구분하고 CLAUDE.md 객관성 원칙 준수
6. 모든 출력은 한국어로 작성

**완료 후**:
1. TaskUpdate로 과제를 completed로 표시
2. SendMessage로 전체 정찰 보고서를 team-lead에게 전송 (type: "message", recipient: "team-lead")
```

### 6단계: 실시간 진행 추적

- 정찰 보고서를 받을 때마다 해당 영역의 핵심 발견 3개를 사용자에게 보여줌
- 4개 보고서가 모두 도착할 때까지 대기
- 모두 도착하면 SendMessage로 4개 Agent에 shutdown_request 전송

### 7단계: team-lead 종합 원인 규명

4개 정찰 보고서를 종합해 **급변 원인 규명 리포트**를 출력합니다 (리서치 리포트가 아니며, 핵심은 "판단"):

- **주가 경로는 kis_flow 일별표의 종가·등락률을 기준으로 씁니다**(KRX 정규장 종가이며 로컬 기준 일봉과 대조됨). Agent가 웹에서 가져온 지연 시세와 1% 넘게 다르면 kis_flow 값을 쓰고 차이를 표기합니다
- 급변 원인 표의 "심리/수급" 후보에는 kis_flow 수치(급변일 외국인·기관·기관 세부 순매수, 프로그램 순매수, 공매도 비중, 대차·신용 잔고 변화)를 증거·반증 칸에 넣습니다

---

#### 1. 한 줄 원인 규명
> 한 단락(30~60자)으로 설명: 이번 주가 급변의 주원인 + 부원인 + 성격 판단(가치 이벤트/심리 변동/불명)

#### 2. 전체 이벤트 타임라인 (4개 영역 통합)

날짜 역순으로 모든 영역의 이벤트를 통합:

| 날짜 | 영역 | 이벤트 | 출처 | 급변 원인 가중치 |

하나에 체크:

- [ ] **가치 이벤트**: 펀더멘털에 실제 변화 발생(실적, 해자, 경영진, 최종 구도) → 투자 논거 재검토 필요

- [ ] **진짜 원인 불명**: 주가 급변 폭에 맞는 이벤트를 찾지 못함 — **가장 위험한 결론**. 시장이 무언가를 먼저 알고 있거나(내부 정보/선반영), 우리가 정보원을 놓쳤을 수 있음
- [ ] **혼합**: 일부 가치 이벤트 + 일부 심리 증폭

## 핵심 원칙

1. **완전함보다 속도** — 이 스킬의 핵심 가치는 10~15분 안에 원인 판단을 내놓는 것. 심층 분석에 빠지지 말 것 (그것은 다른 스킬의 역할)
2. **나열보다 원인 규명** — 이벤트를 찾기는 쉽고, 어려운 것은 "어떤 이벤트가 이번 주가 급변에 걸맞은가"를 판단하는 것. 더하기가 아니라 빼기를 할 것
3. **"불명"을 정직하게** — 주원인을 못 찾으면 "진짜 원인 불명"이라고 명시. 억지로 인과관계를 엮는 것보다 가치 있음 (시장이 악재를 선반영 중일 수 있음)
4. **입장 사전 설정 금지** — 보유 중이라는 이유로 "심리 변동일 뿐, 괜찮다"로 기울지 말 것. 증거가 가리키는 대로 쓸 것
5. **"촉매"와 "우연" 구분** — 같은 시기에 일어난 이벤트가 반드시 급변의 주원인은 아님. 영향의 크기가 맞는지 볼 것
6. **정보 가용성 존중** — C등급 기업은 뉴스를 전혀 못 찾을 수도 있으며, 그 결론 자체를 적어야 함
7. **`CLAUDE.md` 객관성 원칙 준수** — 모든 판단에 데이터 출처 첨부, 사실과 의견 구분
8. **사용자 대신 결정하지 않음** — 원인 규명과 행동 제안 목록은 제시하되, 매매 결정은 사용자가 함
