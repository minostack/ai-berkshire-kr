# 종가매수 후보 스캐너 (설계 closing-0.4)

코스피200 + 코스닥150 종목의 **최근 1개월 일봉 흐름**으로 종가매수 후보를
네 가지 유형으로 뽑습니다.

| 유형 | 패턴 | 핵심 조건 |
|---|---|---|
| **A** | 장대 양봉 → 짧은 도지 2~3일 | 조정 봉 몸통 ≤ 기준봉 몸통의 5%, 종가가 5일선 위 |
| **B** | 장대 양봉 → 4연속 음봉 → 5일째 양봉 | 4일째 5일선 이탈·근접, 5일째 20일선 지지 확인 |
| **C** | 상한가/장대 양봉 → 8~12봉 기간 조정 → 돌파 양봉 | 거래량 다시 증가하며 5일선 돌파 |
| **D** | 거래대금 동반 신고가 | 5·20·60일 신고가 + 거래대금 급증 |

A·B·C는 공통으로 **조정 구간 거래량이 줄어야** 합니다.

**지원 입력 형식**:

```
/closing-bet-scan                      # 로컬 일봉, 최신 거래일 기준 A·B·C·D
/closing-bet-scan live                 # KIS 당일 봉 + 장중 미완료 봉 포함 (15:20 전후 종가매수용)
/closing-bet-scan kis                  # KIS 당일 봉, 완료 봉만 (kiwoom이라고 써도 같음)
/closing-bet-scan date 2026-09-22      # 기준일 지정
/closing-bet-scan A,C                  # 일부 유형만
/closing-bet-scan d20                  # D형 신고가 기준을 20일로 (기본 60, 5/20/60 가능)
/closing-bet-scan extended             # 정규장 복원 못 한 애프터마켓 봉도 사용(비권장)
/closing-bet-scan noprobe              # 시장 최신 거래일 KIS·키움 조회 생략(평일 근사로 알림)
```

**이 스킬은 데이터를 적재하지 않습니다.** 일봉·1분봉·정규장 복원은 적재 프로세스
(16:10 `data-load provisional` — 오늘 잠정 일봉, 익일 08:30 `data-load daily` — 정규장 확정)이
맡습니다. 16:10~익일 08:30 사이 로컬 당일 봉은 **잠정**(1분봉 합, 거래량 근사)입니다.
스캔할 때는 **[데이터 기준] 알림**만 보여 줍니다.

인자는 조합할 수 있습니다(예: `/closing-bet-scan live A,B,C`).

## 실행 절차

### 1단계: 인자 → 명령 변환

| 입력 | 옵션 |
|---|---|
| (없음) | `--source local` |
| `live` | `--source kis --live` |
| `kis` / `kiwoom` | `--source kis` (키움 API를 꼭 써야 할 때만 CLI에서 `--source kiwoom`) |
| `date YYYY-MM-DD` | `--date YYYY-MM-DD` |
| `A,B` 등 유형 문자 | `--types A,B` |
| `d5` / `d20` / `d60` | `--d-period 5` / `20` / `60` |
| `extended` | `--allow-extended` |
| `noprobe` | `--no-probe` |

```bash
python tools/closing_bet_scanner.py [옵션]
```

- 로컬: 약 1분, 네트워크는 시장 최신 거래일 확인 1회뿐(`noprobe`면 없음) → Bash `timeout` 600000 지정
- KIS: **지난 날은 로컬 기준 일봉, 로컬에 없는 날(보통 오늘)만** KIS 일봉(`FHKST03010100`)을
  종목당 1회 조회 — 351종목 약 2분. `.env`에 `KIS_APP_KEY` / `KIS_APP_SECRET` 필요.
  당일 거래량은 **KRX만**(로컬 9/14 이후 봉은 NXT 메인마켓 포함)이라 상대적으로 작게 잡힌다.
  직전 거래일 종가가 로컬과 0.5% 넘게 다르면 수정주가 불일치 경고가 나온다.
  **15:35~16:00 사이 실행**이 가장 정확하다 — 당일 봉이 정규장 확정값이고 애프터마켓(16:00~)이
  아직 섞이지 않는다(봉 기준 `bars-1.0`, 15:30 종가 + 확정 여유 5분)
- 종료 코드: 0 정상 · 2 데이터 없음/설정 오류 · **3 판정 가능한 종목 0개**(→ "후보 없음"으로
  보고하지 말고 원인을 전달)

### 왜 1분봉이 필요한가 (2026-09-14 애프터마켓 도입 이후)

키움 일봉의 종가는 **애프터마켓 최종가(20:00 확정)** 이고 거래량에 애프터마켓이 섞인다
(`configs/market_rules/KRX-2026-09-14-aftermarket.json`). 15:40 종가매수 판단에는 쓸 수
없는 값이다. 스캐너는 저장소의 **정규장 일봉**(봉 기준 `bars-1.0`)을 쓴다. 2026-09-14 이후 봉은
`cvdobv.py daily-cache regular-from-minute`가 1분봉으로 만든 것이다 — 종가는 15:30 종가 단일가
체결 봉(체결이 늦어 15:30~15:35 `OTHER`로 찍힌 봉 포함, 2026-09-17 삼성전기 등), 거래량은
EXTENDED 거래량 − 애프터마켓 1분봉 거래량. 이 규칙 하나를 모든 스캐너가 공유한다(closing-0.2의
즉석 1분봉 합산 복원은 거래량이 공식값보다 작게 나와 0.3에서 없앴다 — 9/1~9/11 대조 하위 1%
구간 77%). 정규장 봉이 없는 날이 판정 창(최근 61봉)에 있으면 그 종목은 **판정 불가**다.

### 2단계: [데이터 기준] 알림 확인

스캔 출력 맨 앞의 `[데이터 기준]`을 사용자에게 그대로 전달합니다(리포트에도 같은 절이 남는다).

| 줄 | 뜻 |
|---|---|
| 봉 기준 bars-1.0 | 일봉 = 정규장·수정주가. 9/14 이후는 1분봉 정규장 복원본 |
| 스캔 기준일 · 시장 최신 완료 거래일 | 시장 최신 거래일은 KIS 005930 일봉 1회 조회(적재 원천과 같은 순서 — `CVD_MARKET_SOURCE=kiwoom`이면 키움 먼저, 실패하면 다른 원천, 둘 다 실패하면 평일 근사 — "추정" 표시. `noprobe`면 바로 근사) |
| ⚠ 로컬 일봉이 …보다 뒤처졌다 | 적재 전이다. 스캔은 로컬 최신일 기준으로 끝까지 하고, 결과가 그 날짜 기준임을 밝힌다 |
| ⚠ 기준일 봉 없는 종목 / 정규장 복원 전 봉 | 그 종목은 판정 불가로 집계된다 |
| → 데이터 적재는 적재 프로세스가 맡는다 | 적재가 필요하다는 **안내**다. 스킬이 적재 명령을 실행하지 않는다 — 사용자에게 `data-load daily`(20:05 이후)를 알리고 끝낸다 |

그 밖의 경고:
- `판정 N`이 유니버스(351)보다 눈에 띄게 적으면 `data/index_stocks.json`(/update-index)
  또는 일봉 수집 누락을 의심
- `제외: 애프터마켓 봉(정규장 복원 불가) N` — 적재 프로세스가 아직 복원하지 않은 날이 판정 창에
  있다. 사용자가 원하면 `extended`로 실행하되 애프터마켓 가격이 섞였다고 명시
- `제외: 중간 거래일 누락 / 봉 부족 / 판정 오류` — 해당 종목은 "후보 없음"이 아니라 판정 불가
- `유형별 판정 가능` — 신규 상장 등으로 60봉 미만이면 D형은 판정 불가로 센다
- `거래대금 추정 봉` — 1분봉 복원 봉의 거래대금은 같은 날 EXTENDED 공식 거래대금 × 정규장
  거래량 비율(추정)이다. EXTENDED 값이 없으면 종가×거래량
- `live` 실행 시 당일 거래량·거래대금은 **마감 전 값** — C형 거래량 증가·D형
  거래대금 조건이 마감 후 판정과 달라질 수 있음

로컬 데이터 갱신은 이 스킬 밖에서 한다(사용자가 실행하거나 스케줄):

```bash
python cvdobv.py data-load daily
```

### 3단계: 결과 보고

리포트는 `reports/종가매수-scan-{YYYYMMDD}-{HHMMSS}.md`에 실행마다 새로 저장됩니다
(`--no-save`로 생략). 리포트 머리에 소스·옵션·제외 사유·봉 성격 집계가 남습니다.
사용자에게는 다음을 간결하게 전달합니다.

1. [데이터 기준] 알림 · 기준일 · 데이터 소스 · 판정 종목 수 · 경고
2. 유형별 종목 수와 목록(코드, 종목명, 종가, 등락, 근거)
3. **여러 유형에 동시 해당**하는 종목(`[중복 유형]` 칸)이 있으면 따로 표시
4. 해당 종목이 없는 유형은 "해당 없음"으로 명시 — A·B·C는 드문 패턴이라 0건인
   날이 흔합니다(1년 × 날짜별 구성종목에서 A 17건 · B 17건 · C 71건)
5. 표의 `봉 성격`이 EXTENDED이면 그 종목은 애프터마켓 가격으로 판정됐다고 밝힌다

보고 원칙(CLAUDE.md): 스캔 결과는 **패턴 충족 사실**만 전달합니다. "좋은 종목",
"매수 적기" 같은 평가를 덧붙이지 않습니다. 개별 종목에 대한 의견은 반드시
"의견"으로 표기하고, 반대 가능성(예: 거래대금 급증이 고점 매물 소화일 수도
있음)도 함께 적습니다.

## 판정 정의 (바꾸면 다른 설계입니다)

값은 모두 `tools/closing_bet_scanner.py` 상단 상수입니다. 바꾸면
`DESIGN_VERSION`을 올리세요.

**장대 양봉(기준봉)**: 몸통 ≥ 시가 × 5% · 몸통 ≥ 고저폭 × 60% · 거래량 ≥ 직전
20일 평균 × 1.5
**상한가**: 전일 종가 대비 +29% 이상 (C형에서 장대 양봉과 동급)

| 유형 | 정의 |
|---|---|
| A | 기준봉 다음날~오늘 2~3봉. 각 봉 \|종가−시가\| ≤ 기준봉 몸통 × 5%, 종가 ≥ MA5 |
| B | 기준봉 +1~+4일 모두 음봉, +4일 종가 ≤ MA5 × 1.01. 오늘(+5일) 양봉, 저가 ≤ MA20 × 1.02, 종가 ≥ MA20 |
| C | 기준봉과 오늘 사이 조정 8~12봉, 조정 최저가 ≥ 기준봉 시가. 오늘 양봉, 종가 > MA5, (전일 종가 ≤ 전일 MA5 또는 시가 ≤ MA5), 거래량 ≥ 조정 평균 × 1.5 |
| 공통(A·B·C) | 조정 구간 평균 거래량 ≤ 기준봉 × 60%, 조정 중 어느 봉도 기준봉 거래량 초과 금지, 거래량 0(거래정지) 봉이 있으면 불충족 |
| D | 오늘 고가 ≥ 직전 N−1봉 최고가 **그리고** 종가 ≥ 직전 N−1봉 최고 종가. 거래대금 ≥ 20일 평균 × 1.5 및 ≥ 100억 원 |
| 유동성 | 직전 20일 평균 거래대금 ≥ 10억 원 |

해석상 선택한 부분:
- A형 "장대 양봉 길이의 5% 이내" → **각 조정 봉의 몸통** 크기 기준으로 해석
- A형 "5일선을 깨지 않고" → **종가** 기준
- C형 "조정 최저가 ≥ 기준봉 시가"는 원 기준에 없던 조건 — 기간 조정(횡보)과
  하락 추세를 구분하려고 추가

## 주의사항

1. **수익성이 확인되지 않았습니다.** 1년 탐색 백테스트(`tools/closing_bet_backtest.py`,
   `reports/종가매수-ABC-백테스트-20250923-20260923.md`)에서 A·B·C 전체 신호의 평균 순수익은
   +0.58%, 95% 구간 [−2.25%, +3.42%]로 0과 구별되지 않았고, A형은 −1.90%였습니다.
   사전등록 없는 탐색 결과이므로 상수를 바꾸려면 `/prereg-backtest`로 새 기간에서 확인하세요
2. 결과는 **패턴 충족 목록**이지 매수 신호가 아닙니다
3. 정렬은 20일 평균 거래대금(유동성) 내림차순 — 순위가 기대수익을 뜻하지 않습니다
4. 판정 불가 종목(기준일 봉 없음·중간 거래일 누락·봉 부족·정규장 복원 불가·판정 오류)은
   사유별로 집계되어 출력·리포트에 남습니다
5. 회귀 테스트: `python -m pytest tests/unit/test_closing_bet_scanner.py`
6. **이 스캔 결과는 투자 권유가 아닙니다** — 반드시 심층 분석 후 최종 판단
