# 사전등록 백테스트 — 가설을 먼저 적고, 적은 대로만 본다

종목 선정 규칙·필터·보유기간 같은 **새 가설을 검증할 때** 쓰는 절차입니다.
결과를 보기 전에 무엇을 볼지·어떻게 판정할지 고정하고(`docs/PREREGISTRATION_*.md`),
그 문서의 sha256을 결과에 박아 **어느 약속으로 돌린 결과인지** 남깁니다.

> 사전등록의 힘은 "미리 적었다"가 아니라 **"적은 대로만 봤다"**에서 온다.
> — `docs/PREREGISTRATION_C.md`

**지원 입력 형식**:

```
/prereg-backtest 가설 설명              # 새 가설 → 사전등록 초안 → 확정 → 실행 → 리포트
/prereg-backtest ledger                 # 사전등록 대장(누적 검정 수·판정) 확인
/prereg-backtest rerun B                # 기존 사전등록 재현 실행 (B, B_HOLD, A, A2, NEGFILTER, AB)
```

---

## 언제 쓰는가 / 쓰지 않는가

| 쓴다 | 쓰지 않는다 |
|---|---|
| 스캐너 게이트·필터·결합·보유기간을 바꿀지 판단할 때 | 이미 사전등록된 결과를 "조금 바꿔서 다시" 볼 때 — 그건 새 사전등록이다 |
| 리서치 문서의 "다음에 시험할 후보"를 검증할 때 | 결과가 마음에 안 들어 임계값을 조정하고 싶을 때 — **하지 않는다** |

## 절차

### 0단계 — 대장부터 본다

```bash
cat docs/PREREGISTRATION_LEDGER.md
```

지금 몇 번째 검정인지, 같은 데이터 가족(D1 일봉 / D2 일봉+DART)에서 몇 번 봤는지 확인한다.
**가족 안 사전등록이 늘수록 새 결과는 할인해서 읽는다.**

### 1단계 — 사전등록 문서 작성 (결과를 보기 전)

`docs/PREREGISTRATION_{이름}.md`. 기존 문서(`_B`, `_A2`, `_AB`)를 틀로 쓴다. 반드시 들어갈 절:

| 절 | 내용 |
|---|---|
| §0 이미 본 것 / 보지 않은 것 | 앞선 결과 중 이 가설의 **출처**가 된 것을 전부 적는다. 출처가 같은 데이터면 "**탐색**"이라고 명시 |
| §1 정의 | 신호·필터를 **코드 함수 이름**까지 적는다(예: `ab_backtest_b.build_panel`, `negfilter.classify`). 실거래 스캐너에서 재현 가능한 정의인지 확인 |
| §2 기간·수익률 | 기간 시작·끝의 **근거**(데이터 가용성, 애프터마켓 도입 2026-09-14 전 청산 등) |
| §3 가설과 검정 | 주가설(가족 BH-FDR), 통계 방식, **판정 규칙**, "미리 적는 예상", 보조(서술용), **하지 않을 것** |
| §4 무엇이 나오면 무엇을 하나 | 판정별 다음 행동 — 스캐너를 바꾸는 조건을 여기서 정한다 |
| §5 기록 | 결과 JSON·리포트 경로 |

문서를 확정한 뒤에는 고치지 않는다. 경로·파일명 같은 비본질적 수정만 **실행 전**에 허용하고 리포트에 적는다.

### 2단계 — 백테스트 코드

`tools/ab_backtest_{이름}.py`. 새로 짜지 말고 아래 부품을 **import**한다 — 같은 정의가 두 벌 생기면
어느 쪽이 맞는지 알 수 없다.

| 부품 | 위치 | 용도 |
|---|---|---|
| `build_panel(horizons, signal_end, suppress_td)` | `tools/ab_backtest_b.py` | B 신호·순수익·유니버스·지수 행렬. 인자 비우면 B 사전등록 그대로 |
| `compute_metrics`, `gate_masks`, `net_return` | 〃 | B 지표(스캐너 `b_metrics`와 봉 단위 일치 — 테스트 고정), 비용 식 |
| `summarize`(이동 블록), `bh_fdr`, `verdict` | 〃 | 신호일 계열 통계·판정 |
| `run(event_date=, extra=)` | `tools/ab_backtest_a.py` | A(PEAD) 이벤트 백테스트 — 이벤트일 훅·보조 분석 훅 |
| `events_with_sue`, `cluster_bootstrap`(분기 군집) | 〃 | 이벤트 시점 SUE, 분기 군집 부트스트랩 |
| `classify`, `summarize_diff` | `tools/ab_backtest_negfilter.py` | 신호일 기준 SUE 판정(정기보고서 기준), **두 집단 차이** 통계 |
| `quarter_events`, `sue_latest`, `prelim_event_date`, `ab_condition` | `tools/ab_candidate_scanner.py` | 스캐너와 백테스트가 공유하는 정의 |

필수 규칙:
- 결과 JSON에 `prereg.sha256`을 넣는다
- **벡터화·재구현한 부분은 스캐너 함수와 같은 값이 나오는지 단위 테스트**로 고정한다
  (`tests/unit/test_ab_backtest_*.py` 참고)
- 공유 코드를 고쳤으면 **기존 사전등록을 다시 돌려 결과가 그대로인지** 확인한다
  (`python tools/ab_backtest_b.py --no-save` 등)

### 3단계 — 실행과 보고

```bash
python tools/ab_backtest_{이름}.py            # 첫 실행 결과를 그대로 보고
```

- 실행 중 버그를 고쳤으면 **결과를 보기 전인지 후인지** 구분해 리포트에 적는다
- 리포트: `reports/{이름}-백테스트-{YYYYMMDD}.md` — 요약 표(관측·95% 구간·MDE·q·판정),
  보조 결과, 해석(사실 / 반면에 / 의견), 한계, 사전등록 §4에 따른 다음 행동
- **`docs/PREREGISTRATION_LEDGER.md`에 한 행 추가** — 결과가 나빠도 추가한다

### 4단계 — 스캐너 반영 (§4가 허락할 때만)

사전등록 §4의 조건을 충족했을 때만 스캐너를 바꾼다. 바꾸면 `DESIGN_VERSION`을 올리고,
스캐너 판정이 백테스트 판정과 같다는 테스트를 붙인다(`test_A조건_판정은_백테스트_AB와_같다` 참고).

## 판정 규칙 (지금까지 공통)

| 판정 | 조건 |
|---|---|
| `SIGNIFICANT_EDGE` | 95% 구간이 0을 제외하고 예측 방향, 가족 BH-FDR q ≤ 0.05 |
| `SIGNIFICANT_NEGATIVE` | 구간이 0을 제외하고 반대 방향 |
| `UNDERPOWERED` | 구간이 0 포함, \|관측\| < MDE(= 2.8 × SE) — **"효과 없음"이라 쓰지 않는다** |
| `NO_SIGNIFICANT_EDGE` | 구간이 0 포함, \|관측\| ≥ MDE |

유의가 나와도 **"발견"이 아니라 "작성일 이후 데이터로 확인할 후보"**라고 쓴다.

통계 선택:
- 매일 신호가 나는 규칙 → 신호일 계열 **이동 블록 부트스트랩**(블록 = 보유기간)
- 신호가 공시 마감일 등에 몰리는 이벤트 → 신호일의 **달력 분기 군집** 부트스트랩
- 한 신호 집합을 둘로 나누는 필터·결합 → 신호 단위 **두 집단 차이**, 분기 군집

## 지금까지의 결과 (2026-09-27)

| 사전등록 | 판정 | 한 줄 |
|---|---|---|
| B | H1 유의 / H2 불가 | 유니버스는 이기지만(+1.09%, 20일) 비용 후 지수와 구별 안 됨 |
| B_HOLD (탐색) | H1 유의 / H2 불가 | 40·60일로 늘려도 같은 구조(+2.01%/+2.93% vs 유니버스) |
| A | 불가 | DART 분기 2016~ → 군집 37개, 검정력 부족 |
| A2 | 불가 | 잠정실적일로 앞당기면 +1.87%(q=0.139), 2026년 한 해 의존 |
| NEGFILTER | 불가 | 방향은 예측대로(-1.21%p), 반기간 부호 반전 |
| AB (탐색) | H1 유의(q=0.03) / H2 불가 | B 중 SUE≥1이 나머지보다 나음 — 대장 누적 고려 시 할인 |

**공통 교훈**
1. **동일가중 유니버스는 16년간 KOSPI200 지수에 크게 뒤졌다.** 유니버스 대비(H1) 유의가
   지수 대비(H2) 우위로 이어지지 않는다 — 두 가설을 **항상 함께** 등록한다
2. **DART 기반 가설은 2016년 이후뿐이다.** 분기 군집 ~38개 → MDE가 크다. 예상 결과에
   `UNDERPOWERED`를 미리 적어 둔다
3. **실거래 재현성** — 잠정실적일 이벤트(A2)는 SUE 확정치를 미리 본다. 스캐너가 재현할 수
   없는 정의로 낸 수익률을 기대수익으로 읽지 않는다
4. 거래세 0.18% 고정(과거 실제 세율이 더 높음), 배당 미반영, 포트폴리오 제약 없음 —
   모든 결과의 공통 한계

## 주의사항

1. **임계값·기간·h를 결과를 보고 바꾸지 않는다.** 바꾸고 싶으면 새 사전등록 + 대장 한 행
2. **보조 결과에서 좋은 칸을 주 결과로 올리지 않는다**
3. 2026-09-14 이후 일봉은 애프터마켓 포함(EXTENDED)이다 — 백테스트 청산이 그 전에 끝나도록 기간을 자른다
4. 이 절차의 산출물은 리서치 기록이며 **투자 권유가 아니다**
